# v0.20.0 批量操作 API — 实施计划

## 1. 当前代码现状理解

### 已有能力
- 单条审核：POST /v1/docs/{id}/review
- 单条发布：POST /v1/docs/{id}/publish
- 单条驳回：POST /v1/docs/{id}/reject
- 单条删除资料：无（资料无 delete API，但项目有）

### 缺失环节
- 用户有 50 个草稿文档时，必须逐个点审核，体验差
- 无法一次性发布多个审核通过的文档

---

## 2. 本轮实施计划

### 目标
新增 3 个批量操作端点：
1. `POST /v1/docs/batch/review` — 批量审核
2. `POST /v1/docs/batch/publish` — 批量发布
3. `POST /v1/docs/batch/reject` — 批量驳回

### 请求格式
```json
{"doc_ids": ["uuid1", "uuid2", ...]}
```

### 响应格式
```json
{
  "data": {
    "succeeded": ["uuid1", "uuid2"],
    "failed": [{"id": "uuid3", "reason": "只有草稿状态的文档可以提交审核"}]
  }
}
```

### 设计要点
- 部分成功 — 一个失败不影响其他
- 逐条调用现有 service 方法（复用逻辑，不绕过校验）
- 每条成功的都写审计日志

## 4. 实现约束

1. **复用现有 service 方法** — 不新增 service 层批量方法
2. **部分成功** — 不用事务包裹全部，每条独立 try/except
3. **权限与单条一致** — batch review 需要 reviewer，batch publish 需要 project_admin
4. **上限 50 条** — 防止一次操作过多
