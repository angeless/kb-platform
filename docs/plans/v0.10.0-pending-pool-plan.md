# v0.10.0 架构节点待确认池 — 实施计划

## 1. 当前代码现状理解

### 已有能力
- `KnowledgeDoc.node_id` 可为 NULL（已由 v0.8.0 增量接入创建 `node_id=None` 的文档）
- `GET /v1/docs?project_id=xxx` 列出所有文档，但无法按 `node_id=None` 筛选
- `ArchitectureNode` CRUD 已有（create_node, update_node）
- 冲突记录也有 `node_id=None` 的情况

### 缺失环节
- 没有"待确认池"筛选端点 — 用户无法快速找到所有未绑定节点的文档
- 没有"绑定节点"端点 — 用户无法将待确认文档手动绑定到架构节点
- PRD doc 03 section 8："若无法绑定，则进入待确认节点池"

### 需求定义
1. 列出未绑定架构节点的文档（待确认池）
2. 将文档绑定到架构节点
3. 列出未绑定节点的冲突记录

---

## 2. 本轮实施计划

### 目标
1. `GET /v1/docs/pending` — 列出 `node_id=NULL` 的待确认文档
2. `POST /v1/docs/{id}/assign-node` — 将文档绑定到指定架构节点
3. `GET /v1/conflicts/pending` — 列出 `node_id=NULL` 的待确认冲突

### 实现方式
- 在现有 doc_service 和 conflict_service 中新增方法
- 在现有 docs 和 conflicts router 中新增端点
- 不新建文件，不新建服务

## 4. 实现约束

1. **不新增数据库表** — 利用现有 node_id=NULL 条件
2. **不修改已有逻辑** — 只新增方法和端点
3. **assign_node 需验证节点存在** — 不能绑定到不存在的节点
4. **租户隔离** — 通过 project→tenant 链路保证
