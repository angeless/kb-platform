# V0.2.0 实施计划：MinIO 实际文件上传

## 当前代码现状理解

### 已有能力
- `asset_service.py` 的 `upload()` 方法：接收文件字节 → 计算 SHA-256 → 检查重复 → 创建 Asset 记录
- `assets.py` 路由的 `POST /v1/assets/upload`：接收 multipart 文件 → 调用 service → 返回 AssetOut
- object_path 当前写死为 `pending/{project_id}/{filename}`，**不实际上传到 MinIO**
- 配置已有：`s3_endpoint`, `s3_access_key`, `s3_secret_key`, `s3_bucket`, `s3_region`（在 shared-config settings.py）
- docker-compose.yml 已有 MinIO 服务定义
- 现有 5 个 asset 测试全部通过

### 差距
- 无 S3/MinIO 客户端封装
- upload 方法不实际写文件到对象存储
- 无文件类型白名单校验
- 无文件大小校验
- object_path 不是真实存储路径

## 本轮实施计划

### 目标
在不破坏现有 63 个测试的前提下，为 upload 端点接入真实 MinIO 文件上传，使上传的文件实际存储到对象存储中。

### 实现方案
1. 新建 `app/utils/storage.py` — 封装 S3 客户端（基于 boto3），提供 `upload_file()` 和 `ensure_bucket()` 方法
2. 修改 `asset_service.py` — 在创建 Asset 记录前调用 storage 上传文件，生成真实的 object_path
3. 修改 `assets.py` 路由 — 增加文件大小和类型校验
4. 补充测试 — 使用 mock 替代真实 MinIO 调用（测试环境不依赖 MinIO 服务）
5. 回归全部 63 个已有测试

## 预计修改文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `services/api/app/utils/storage.py` | **新建** | S3 客户端封装 |
| `services/api/app/services/asset_service.py` | **修改** | 接入 storage 上传 |
| `services/api/app/routers/assets.py` | **修改** | 增加文件大小/类型校验 |
| `services/api/tests/test_assets.py` | **修改** | 补充 MinIO 上传测试 + mock |
| `services/api/tests/conftest.py` | **修改** | 增加 mock storage fixture |

## 实现约束

1. **不破坏已有测试** — 现有 63 个测试必须全部继续通过
2. **不修改 shared-models** — Asset 模型不改动
3. **不修改 shared-config** — S3 配置项已齐全
4. **测试不依赖真实 MinIO** — 使用 unittest.mock 替代 S3 调用
5. **文件类型白名单** — 按 PRD 7.1 和设计文档 5.4：image/audio/video/pdf/doc/url/zip/text
6. **文件大小限制** — 默认 100MB（来自 settings.max_upload_size_mb）
7. **object_path 格式** — `{tenant_id}/{project_id}/{asset_id}/{filename}`
