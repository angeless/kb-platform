# v0.11.0 审计日志 — 实施计划

## 1. 当前代码现状理解

### 已有能力
- `AuditLog` 模型已定义（audit.py）：tenant_id, project_id, user_id, action, resource_type, resource_id, detail
- 模型已在 `__init__.py` 中导出
- 数据库索引已配置

### 缺失环节
- 没有审计日志写入逻辑 — 关键操作（上传、审核、发布、架构修改、密钥操作）不记录审计
- 没有审计日志查询 API — 管理员无法查看审计记录
- 设计规格 section 8.2 要求："关键操作写入 audit_log 表"

### 需求定义（设计规格 section 8.2）
覆盖操作：上传、审核、发布、回滚、架构修改、密钥操作

---

## 2. 本轮实施计划

### 目标
1. 新建 `audit_service.py` — 写入和查询审计日志
2. 在关键 service 方法中调用 audit 写入
3. 新建 `GET /v1/audit-logs` — 查询审计记录

### 写入审计的位置
| 操作 | 文件 | action | resource_type |
|------|------|--------|---------------|
| 上传文件 | asset_service.upload | upload | asset |
| 审核文档 | doc_service.review | review | knowledge_doc |
| 发布文档 | doc_service.publish | publish | knowledge_doc |
| 架构发布 | architecture_service.publish | publish | architecture |
| 创建模型供应商 | model_provider_service.create_provider | create | model_provider |
| 绑定节点 | doc_service.assign_node | assign_node | knowledge_doc |
| 解决冲突 | conflict_service.resolve | resolve | conflict |

### 设计要点
- audit_service 使用**独立方法调用**，不用中间件/装饰器（保持简单、显式）
- service 方法中调用 `await self.audit(action, resource_type, resource_id, detail)`
- 查询端点支持按 project_id、action、resource_type 筛选

## 4. 实现约束

1. **不新增数据库表** — AuditLog 表已存在
2. **审计写入不阻塞业务** — 写入失败只 log warning，不影响主操作
3. **不改已有方法签名** — 只在方法内部追加审计调用
4. **审计日志不设外键** — 已有设计（防级联删除）
