## 一、当前代码现状理解

### upload() 方法（asset_service.py:33-94）
当前顺序：
1. 验证文件扩展名和大小
2. 计算 SHA-256 + 查重
3. **先上传 MinIO**（第 76-77 行）✅ 顺序已正确
4. **再创建 DB 记录 + flush**（第 81-93 行）

### import_url() 方法（asset_service.py:96-151）
当前顺序：
1. 下载 URL 内容
2. 计算 hash + 查重
3. **先上传 MinIO**（第 134-135 行）✅ 顺序已正确
4. **再创建 DB 记录 + flush**（第 137-150 行）

### 现状分析
- 文件上传顺序**已经正确**（先 MinIO 后 DB），开发计划描述的"先 DB 后 MinIO"问题不存在
- **缺失**: 如果 DB flush 失败（如并发 hash 重复），MinIO 上已上传的文件不会被清理，导致孤儿文件
- **缺失**: StorageClient 没有 `delete_file()` 方法

### StorageClient（storage.py:66-97）
- 只有 `upload_file()` 和 `ensure_bucket()`
- 缺少 `delete_file()` 方法

## 二、本轮实施计划

1. 在 StorageClient 中添加 `delete_file()` 方法
2. 在 upload() 中，wrap DB flush in try/except，失败时 best-effort 删除 MinIO 文件
3. 在 import_url() 中同样处理
4. best-effort 删除：try delete，except 只 log warning，不再抛异常
5. 编写测试验证
