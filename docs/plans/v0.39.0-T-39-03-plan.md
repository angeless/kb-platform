## 一、当前代码现状理解

### 1.1 项目根目录无 .dockerignore

当前不存在 `.dockerignore` 文件，Docker 构建上下文包含整个项目根目录的所有文件，包括：
- `.git` 目录（数百 MB，完全不需要）
- `.env` 文件（包含敏感配置）
- `node_modules` 目录
- `__pycache__` / `.pytest_cache`
- 文档文件（`docs/`、`*.md`）
- 安全审计报告等非构建文件

### 1.2 Dockerfile 实际 COPY 的路径

从 4 个 Dockerfile 的 COPY 指令分析，构建上下文中 **必须保留** 的路径：

| 路径 | 使用者 |
|------|--------|
| `packages/` | 全部 4 个 Dockerfile |
| `services/api/` | api.Dockerfile |
| `services/ingestion-worker/` | ingestion-worker.Dockerfile |
| `services/pipeline-worker/` | pipeline-worker.Dockerfile |
| `services/ai-orchestrator/` | ai-orchestrator.Dockerfile |
| `.env.example` | ingestion-worker、ai-orchestrator |
| `infra/sql/` | api.Dockerfile |
| `infra/docker/api-entrypoint.sh` | api.Dockerfile |

### 1.3 可以安全排除的内容

- `.git/` — 版本控制，构建不需要
- `.env`、`.env.*`（但保留 `.env.example`）— 防止泄露
- `node_modules/`、`apps/web/node_modules/`、`apps/web/.next/` — 前端构建产物
- `__pycache__/`、`*.pyc`、`.pytest_cache/` — Python 缓存
- `.DS_Store` — macOS 文件
- `docs/` — 文档
- `*.md`（但保留项目根目录 `.env.example`）— Markdown 文档
- `.github/` — CI/CD 配置
- `.claude/` — Claude Code 配置
- 安全审计相关文件（`SECURITY_*`）

## 二、本轮实施计划

1. 在项目根目录创建 `.dockerignore` 文件
2. 按 PRD 中定义的忽略列表添加条目
3. 额外添加 PRD 未列出但应排除的目录（`.github/`、`.claude/`、审计报告等）
4. 验证所有 Dockerfile COPY 引用的路径未被排除

## 四、实现约束

1. 只新增 `.dockerignore`，不修改任何 Dockerfile
2. 不修改 `docker-compose.yml`
3. 必须保留 Dockerfile COPY 引用的所有路径
4. `.env.example` 必须保留（`!.env.example` 取反规则）
