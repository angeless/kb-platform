# v0.13.0 流水线贯通 — 实施计划

## 1. 当前代码现状理解

### 已有能力
- `job_service.create()` **已包含** Celery send_task() 调用（lazy-load 模式）
- `ingestion-worker` 有完整的 celery_app + tasks（parse_asset）
- `ai-orchestrator` 有完整的 celery_app + tasks（propose_architecture / generate_docs / classify_incremental）
- 两个 worker 都有 pyproject.toml、依赖定义

### 缺失环节
- **docker-compose.yml 缺少 ingestion-worker 和 ai-orchestrator 服务定义**
  - 导致 `docker-compose up` 后只有 API + 基础设施，worker 不启动
  - 所有 Job 创建后任务无人消费，永远 pending
- **缺少两个 worker 的 Dockerfile**
  - infra/docker/ 目录只有 api.Dockerfile
- **缺少 Alembic 迁移配置**
  - infra/sql/ 目录为空，新部署需手动建表
- **retry() 不重新派发 Celery 任务**
  - 只把 status 改回 pending，不重新 send_task

---

## 2. 本轮实施计划

### 目标
1. 新建两个 worker 的 Dockerfile
2. 在 docker-compose.yml 中添加 ingestion-worker 和 ai-orchestrator 服务
3. 初始化 Alembic 迁移配置，生成初始迁移脚本
4. 修复 retry() 重新派发 Celery 任务

### 不做的事
- 不添加新解析器（TextParser 足以验证流水线贯通）
- 不改任何 service 业务逻辑
- 不改 AI Orchestrator 的 Prompt 或 LLM 调用

## 4. 实现约束

1. **不改已有 worker 代码** — 只加 Dockerfile 和 compose 配置
2. **worker 服务共享同一网络** — 使用 docker-compose 默认 bridge 网络
3. **环境变量与 API 服务一致** — DB、Redis、MinIO 连接信息复用
4. **Alembic 使用 sync database_url** — 迁移工具不需要 async
5. **retry 逻辑复用 create 中的 dispatch 代码** — 提取为私有方法避免重复
