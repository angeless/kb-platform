## 一、当前代码现状理解

### _extract_identity()（rate_limit.py:50-69）
- 从 Authorization header 提取 Bearer token
- 使用 `jwt.decode()` 解码，但 `options={"verify_exp": False}` 跳过过期检查
- 解码成功后提取 `tenant_id`，返回 `f"tenant:{tid}"`
- 任何异常都 fallback 到 IP 限流
- **问题**：过期 JWT 仍然被当作有效 tenant 身份，攻击者可以使用过期 token 绕过 IP 级限流

### 修复要点
- 将 `verify_exp: False` 改为 `verify_exp: True`（或直接移除该选项，因为默认就是 True）
- 过期 token 会抛出 `jwt.ExpiredSignatureError`，被已有的 `except Exception: pass` 捕获
- 自动回退到 IP 限流

---

## 二、本轮实施计划

1. 将 `options={"verify_exp": False}` 改为移除该选项（默认 verify_exp=True）
2. 无需额外改 except 逻辑（已有 `except Exception: pass` 会捕获 ExpiredSignatureError）
3. 编写测试验证：有效 JWT 使用 tenant 限流、过期 JWT 回退 IP 限流、无 JWT 使用 IP 限流
