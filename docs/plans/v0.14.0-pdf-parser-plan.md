# v0.14.0 PDF 解析器 — 实施计划

## 1. 当前代码现状理解

### 已有能力
- 解析器接口：`parse(content: bytes, filename: str) -> list[dict]`
- 解析器注册表：`PARSERS` 字典，按 asset_type 路由
- TextParser 已实现（按段落切分）
- parse_asset 任务中已有 `get_parser()` 调用，支持新解析器即插即用

### 缺失环节
- 只有 text_parser，不支持 PDF
- 上传 PDF 文件后 asset_type 通过 `guess_asset_type(filename)` 推断，但无对应 parser
- `get_parser("pdf")` 返回 None → 任务 failed

### 需求定义（PRD 7.2）
> 支持 OCR、语音转写、视频拆解、文档解析、网页正文抽取

本轮聚焦"文档解析"中的 PDF 解析。

---

## 2. 本轮实施计划

### 目标
1. 新建 `pdf_parser.py` — 使用 pymupdf 按页提取文本
2. 在 PARSERS 注册表中注册 `"pdf"` 和 `"document"` 类型
3. 在 ingestion-worker 的 pyproject.toml 中添加 pymupdf 依赖
4. 补充 PDF 解析测试

### 设计要点
- 按页切分（每页一个 chunk），page_or_timestamp 记录页码
- 空页跳过
- 支持中文 PDF（pymupdf 原生支持）
- 如果页内文本过长（>5000字符），按段落二次切分

## 4. 实现约束

1. **只加解析器** — 不改任务流程、不改 API
2. **pymupdf 无系统依赖** — 纯 Python 安装，Docker 镜像不需要额外系统包
3. **空页/扫描页处理** — 提取不到文字的页跳过（不报错）
4. **编码安全** — pymupdf 返回 unicode 字符串，无编码问题
