**任务编号**: T-36-02
**所属版本**: v0.36.0
**日期**: 2026-03-19
**基线 commit**: af3a255

---

## 一、当前代码现状理解

### 搜索链路
1. 用户通过 API `GET /v1/search/text` 传入 `query` 字符串
2. `SearchService.text_search()` 调用 `_build_tsquery(query)` 构建 tsquery 字符串
3. `_build_tsquery()` 将用户输入按空格拆分，用 `&` 连接并附加 `:*` 前缀匹配符
4. 构建后的字符串传给 SQL 的 `to_tsquery('simple', :tsquery)` 参数绑定执行

### 问题
- `_build_tsquery()` **不清洗 tsquery 操作符**（`& | ! ( ) : * < >`）
- 如果用户输入 `hello&world` → 生成 `hello&world:*` → `to_tsquery` 解析成两个 token，但中间的 `&` 被错误处理
- 如果用户输入 `hello(world` → 生成 `hello(world:*` → `to_tsquery` 解析失败，抛出 ProgrammingError → 返回 500
- 如果用户输入 `!!!` → 生成 `!!!:*` → `to_tsquery` 解析失败 → 500

### 关键约束
- 这不是 SQL 注入（参数使用 `:tsquery` 绑定，不是字符串拼接到 SQL 中）
- 但是 tsquery 语法错误会导致 PostgreSQL 抛出异常 → 服务端 500 → 用户体验中断

---

## 二、本轮实施计划

### 修改策略
1. 重写 `_build_tsquery()` 函数，在构建 tsquery 前清洗用户输入
2. 清洗规则：
   - 移除所有 tsquery 操作符字符：`& | ! ( ) : * < >`
   - 剥离首尾空白
   - 将连续空格压缩为单个空格
3. 清洗后为空则返回空字符串（`text_search()` 已有处理：tsquery_str 为空时走 ILIKE）
4. 改用 `plainto_tsquery('simple', ...)` 替代 `to_tsquery('simple', ...)`，让 PostgreSQL 自动处理分词
5. `_build_tsquery()` 仅返回清洗后的纯文本，不再手动拼接 `&` 和 `:*`
6. `_tsvector_search()` 中 SQL 从 `to_tsquery` 改为 `plainto_tsquery`

### 不修改的部分
- 不修改 ILIKE 搜索逻辑
- 不修改语义搜索
- 不修改搜索 API 契约（路径、参数、返回结构）
- 不修改 `_extract_snippet()`

## 四、实现约束

1. 清洗后的文本仍通过参数绑定传入 SQL，不存在注入风险
2. `plainto_tsquery` 会自动用 `&` 连接词（AND 语义），与原逻辑一致
3. `plainto_tsquery` 不支持前缀匹配（`:*`），这是与原逻辑的差异——但原逻辑的前缀匹配在 CJK 文本下意义不大（'simple' 配置按字符分词），且代码已有 ILIKE 回退
4. 如果 `plainto_tsquery` 返回空查询（全是停用词等），count 会为 0，自动回退到 ILIKE
