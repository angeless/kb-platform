# v0.9.0 文档版本比对 — 实施计划

## 1. 当前代码现状理解

### 已有能力
- `GET /v1/docs/{id}` 返回文档详情含所有版本列表
- `GET /v1/docs/{id}/versions/{version}` 返回特定版本
- KnowledgeDocVersion 存储 content_md（Markdown 正文）和 change_reason
- 增量接入（v0.8.0）会创建新版本（supplement/correction），追加不覆盖

### 缺失环节
- 没有版本比对端点 — 用户无法看到两个版本之间的具体差异
- 没有 diff 计算逻辑
- PRD doc 04 要求"每次补充、修正和废弃都要写版本记录"，但用户无法直观看到变更内容

### 需求定义
Sprint 3 任务"文档版本比对"— 用户应能对比同一文档的两个版本，看到新增、删除、修改的内容。

---

## 2. 本轮实施计划

### 目标
新增 `GET /v1/docs/{id}/diff?from_version=1&to_version=2` 端点，返回两个版本之间的行级差异。

### 实现方案
使用 Python 标准库 `difflib.unified_diff` 计算行级差异，不引入外部依赖。

### 输出格式
```json
{
  "data": {
    "doc_id": "uuid",
    "from_version": 1,
    "to_version": 2,
    "from_change_reason": "AI 初次生成",
    "to_change_reason": "增量接入 - 补充: 新增退款时效说明",
    "diff_lines": [
      {"type": "context", "content": "# 退款规则"},
      {"type": "removed", "content": "- 退款时效：3-5天"},
      {"type": "added", "content": "- 退款时效：1-3天（加急通道）"},
      {"type": "context", "content": "## 适用范围"}
    ],
    "stats": {"added": 5, "removed": 3, "unchanged": 20}
  }
}
```

## 4. 实现约束

1. **使用标准库** — `difflib.unified_diff`，不引入外部依赖
2. **不新增数据库表** — diff 是实时计算，不存储
3. **不修改已有逻辑** — 只新增 schema/service/router 代码
4. **租户隔离** — 通过 doc_service.get() 保证
