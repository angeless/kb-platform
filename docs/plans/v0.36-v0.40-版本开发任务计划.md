## 第一章 开发管理（总原则）

### 1.1 不推倒重写

本计划所有任务均基于 v0.35.1 现有代码增量修复和增强。禁止重构无关模块、禁止重写已有业务逻辑、禁止变更已有 API 契约（除非本计划明确要求）。

### 1.2 继承已有能力

以下模块/能力已存在且稳定，本计划只在其上做最小改动：

**后端服务层** (services/api/app/services/):
- AuthService: 注册/登录/刷新（JWT HS256）
- ProjectService: 项目 CRUD（租户隔离）
- UserService: 用户邀请/管理
- AssetService: 上传/URL导入/ZIP导入（含 SSRF 防护、路径穿越检测）
- DocService(TenantService): 文档 CRUD/审核/发布/版本/diff
- ArchitectureService(TenantService): 架构树管理/fork/compare/rollback
- SearchService(TenantService): 全文 tsvector + ILIKE 回退
- EmbeddingService(TenantService): pgvector + JSONB 双模式
- ExportService(TenantService): 单文档 Markdown + 项目 ZIP 导出
- JobService(TenantService): 任务创建/重试/Celery 派发
- ConflictService(TenantService): 冲突列表/解决
- AuditService: 审计日志记录/查询
- ModelProviderService: 模型配置加密存储/路由管理

**中间件** (services/api/app/middleware/):
- RateLimitMiddleware: Redis 滑动窗口限流
- MetricsMiddleware: Prometheus 指标
- RequestIdMiddleware: 请求追踪 ID

**工具层** (services/api/app/utils/):
- security.py: bcrypt + JWT
- crypto.py: AES-256-GCM
- storage.py: MinIO/S3 客户端
- url_fetcher.py: SSRF 防护

**Worker 服务**:
- ingestion-worker: text/pdf/ocr/asr 解析器
- pipeline-worker: 9 阶段流水线
- ai-orchestrator: LLM 调用/分类/生成/架构提议

**前端** (apps/web/):
- Next.js 15 / React 19 / TypeScript / Tailwind CSS
- 认证页面（登录/注册）
- 项目管理页面组
- 文档管理/编辑/审核/diff 页面
- 架构树编辑器
- 搜索页面（全文+语义）
- 系统管理页面（模型/用户/审计）

**基础设施**:
- docker-compose.yml（7 服务 + 2 卷）
- Alembic 4 个迁移脚本
- CI/CD (ci.yml + build.yml)
- Prometheus + Grafana 监控栈
- 16 张数据库表（实际 15 张，doc_embedding 缺失）

### 1.3 最小改动原则

每个任务只改必须改的文件。如果发现无关问题，记录到"衍生任务"但不执行。

### 1.4 任务领取规则

每次只能领取一个任务。完成后按第十一章格式汇报，确认后再领下一个。

### T-36-02: 修复搜索 SQL 注入风险

**目标**: 用户输入特殊字符（`&`、`(`、`|`、`!`、`:`）时搜索不崩溃。

**改动范围**:
- 修改: `services/api/app/services/search_service.py` — `_tsvector_search()` 方法

**新增数据库表**: 无

**已有表变更**: 无

**API 定义**: 无（现有端点行为修复）

**业务规则**:
1. 在构建 tsquery 之前，对用户输入进行清洗：
   - 移除所有 tsquery 操作符: `& | ! ( ) : * < >`
   - 剥离首尾空白
   - 将连续空格压缩为单个空格
2. 清洗后如果为空字符串，返回空结果列表和 total=0（不执行数据库查询）
3. 将清洗后的词用 `plainto_tsquery('simple', ?)` 替代当前的手动 tsquery 拼接
4. `plainto_tsquery` 会自动处理分词和转义，支持 CJK（使用 'simple' config）
5. 如果 `plainto_tsquery` 返回空查询（全是停用词），回退到 ILIKE 搜索

**前端变更**: 无

**不做什么**: 不修改 ILIKE 搜索逻辑、不修改语义搜索、不修改搜索 API 契约

**验收标准**:
- [ ] 搜索 `hello&world` 返回正常结果（不是 500）
- [ ] 搜索 `hello(world` 返回正常结果
- [ ] 搜索 `!!!` 返回空结果（不是 500）
- [ ] 搜索空字符串返回空结果
- [ ] 搜索 `"正常中文"` 返回正常结果
- [ ] 搜索 `a & b | c` 返回包含这些词的结果
- [ ] 现有正常搜索功能不受影响（回归）

### T-36-03: 修复 IDOR 跨租户节点分配

**目标**: 文档分配节点时验证目标节点属于同一项目的架构。

**改动范围**:
- 修改: `services/api/app/services/doc_service.py` — `assign_node()` 方法

**新增数据库表**: 无

**已有表变更**: 无

**API 定义**: 无（现有端点行为修复）

**业务规则**:
1. 在 `assign_node()` 中，查询 `ArchitectureNode` 时增加条件：
   - 该 node 所属的 `Architecture.project_id` 必须等于该 doc 的 `project_id`
2. 具体步骤：
   a. 获取 doc（已有逻辑，包含 tenant 验证）
   b. 查询 node，JOIN architecture 表
   c. 验证 architecture.project_id == doc.project_id
   d. 如不匹配，抛出 NotFoundException（不暴露其他项目的节点存在信息）
3. 错误码: `NODE_NOT_FOUND`

### T-40-01: 忘记密码流程

**目标**: 用户可通过邮箱自助重置密码。

**改动范围**:
- 修改: `services/api/app/services/auth_service.py` — 新增方法
- 修改: `services/api/app/routers/auth.py` — 新增端点
- 新增: `apps/web/src/app/forgot-password/page.tsx`
- 新增: `apps/web/src/app/reset-password/page.tsx`
- 修改: `apps/web/src/app/login/page.tsx` — 添加链接

**新增数据库表**: 无

**已有表变更**:
- `user` 表新增:
  - `reset_token` VARCHAR(255) nullable — 重置 token（SHA-256 hash）
  - `reset_token_expires_at` TIMESTAMPTZ nullable — 过期时间

**API 定义**:
- `POST /v1/auth/forgot-password`
  - 方法: POST
  - 权限: 公开
  - 入参: `{"email": "string"}`
  - 响应: 200 `{"message": "如果该邮箱已注册，重置链接已发送"}`
  - 说明: 无论 email 是否存在都返回相同响应（防用户枚举）

- `POST /v1/auth/reset-password`
  - 方法: POST
  - 权限: 公开（通过 token 验证）
  - 入参: `{"token": "string", "new_password": "string"}`
  - 响应: 200 `{"message": "密码重置成功"}`
  - 错误: 400 "重置链接无效或已过期"

**业务规则**:
1. forgot-password:
   a. 生成 32 字节随机 token（secrets.token_urlsafe）
   b. 存储 SHA-256(token) 到 user.reset_token
   c. 设置 reset_token_expires_at 为当前时间 + 1 小时
   d. **本版本暂不实现邮件发送**——将 token 写入 audit_log 并在 API 响应中返回（仅开发/测试用）
   e. 生产环境需接入邮件服务（记为衍生任务）
2. reset-password:
   a. 计算 SHA-256(input_token)
   b. 查询 user.reset_token 匹配 + reset_token_expires_at > now()
   c. 匹配则更新 password_hash，清除 reset_token 和 reset_token_expires_at
   d. 密码强度校验使用已有的 RegisterRequest 规则

**前端变更**:
- 新增: 忘记密码页面（输入邮箱）
- 新增: 重置密码页面（输入新密码，URL 含 token 参数）
- 修改: 登录页面添加"忘记密码？"链接

**不做什么**: 不实现邮件发送服务

**验收标准**:
- [ ] 提交忘记密码请求返回 200（无论 email 是否存在）
- [ ] 使用有效 token 重置密码成功
- [ ] 使用过期 token 重置密码返回 400
- [ ] 重置后旧密码登录失败，新密码登录成功
- [ ] token 使用一次后失效
- [ ] 前端忘记密码→重置密码流程可走通
