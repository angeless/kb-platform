## 一、当前代码现状理解

### 1.1 import_archive() 现状

- 文件: `services/api/app/services/asset_service.py`，第 168-262 行
- 当前已有防护：
  - 文件数限制: max_files = 100（第 190 行）
  - 路径穿越检测: normpath + `..` 检查（第 201-207 行）
  - 文件类型白名单: `is_allowed_file()` 过滤（第 217-219 行）
- **缺失防护**：
  - 无单文件解压大小限制（一个 2GB 的文件会被完整读入内存）
  - 无总解压大小累计限制（100 个大文件可耗尽内存/磁盘）
  - 无压缩比检查（ZIP 炸弹的典型特征是超高压缩比）

### 1.2 ZipInfo 可用信息

- `ZipInfo.file_size`: 未压缩大小（字节）
- `ZipInfo.compress_size`: 压缩大小（字节）
- 这些信息在 `zf.read()` 之前就可获取，可做预检

## 二、本轮实施计划

### 2.1 修改目标

在 `import_archive()` 的解压循环中增加三重大小防护：

1. **单文件大小限制**: 100MB（与 upload 限制一致，使用 `self.max_upload_size_bytes`）
2. **总解压大小限制**: 500MB
3. **压缩比检查**: compressed_size > 0 且 uncompressed_size / compressed_size > 100 时跳过

### 2.2 具体步骤

在 `import_archive()` 的文件遍历循环中（第 209 行之后）：

1. 通过 `zf.getinfo(entry_name)` 获取 `ZipInfo`
2. 检查压缩比 > 100 → 跳过并记录 warning
3. 检查 `info.file_size > self.max_upload_size_bytes` → 跳过并记录 error
4. 累加 `total_decompressed += info.file_size`
5. 如果 `total_decompressed > MAX_TOTAL_DECOMPRESSED`(500MB) → 停止解压，返回已处理结果 + 错误信息
6. 读取文件内容后，再次验证实际大小（防御伪造 ZipInfo）

## 四、实现约束

1. 只改 `import_archive()` 方法的解压循环部分
2. 单文件限制复用 `self.max_upload_size_bytes`（100MB）
3. 总解压限制定义为模块级常量 `MAX_ARCHIVE_TOTAL_BYTES = 500 * 1024 * 1024`
4. 压缩比阈值定义为模块级常量 `MAX_COMPRESSION_RATIO = 100`
5. 超过总限制时停止解压，返回已处理结果（不抛异常，因为已处理的文件有效）
6. 跳过的文件计入 `errors` 列表，写明原因
