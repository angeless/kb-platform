# v0.6.0 文档详情增强（来源绑定与版本记录）— 实施计划

## 1. 当前代码现状理解

### 已有能力
- `GET /v1/docs/{id}` 端点存在，返回 `KnowledgeDocOut`（id, title, status, doc_type 等元信息）
- `POST /v1/docs/{id}/review` 和 `POST /v1/docs/{id}/publish` 状态流转已实现
- `KnowledgeDoc` 模型有 `versions` relationship（lazy="selectin"）
- `KnowledgeDocVersion` 模型有 `source_refs` relationship（lazy="selectin"）
- v0.5.0 的 `generate_docs` 任务已写入 KnowledgeDocVersion + SourceRef 记录

### 缺失环节
- `GET /v1/docs/{id}` 响应中 **不包含版本列表和 Markdown 正文**
- `DocVersionOut` schema 存在但 **不包含 source_refs**
- 用户无法查看文档的实际内容和来源追溯
- 没有独立的"获取特定版本"端点

### 根因
- `KnowledgeDocOut` schema 只定义了元信息字段，没有 `versions` 字段
- `DocVersionOut` schema 没有 `source_refs` 字段
- `doc_service.get()` 虽然会通过 selectin 加载 versions，但 schema 序列化时被忽略

---

## 2. 本轮实施计划

### 目标
增强文档详情 API，使其返回完整的版本内容和来源追溯信息，满足 Sprint 2"来源绑定与版本记录"需求。

### 具体改动

1. **增强 Schema** — 在 `shared_schemas/knowledge.py` 中：
   - 新增 `SourceRefOut` schema
   - 在 `DocVersionOut` 中添加 `source_refs: list[SourceRefOut]` 字段
   - 新增 `KnowledgeDocDetailOut` schema，包含 `versions: list[DocVersionOut]`

2. **增强 Router** — 在 `routers/docs.py` 中：
   - 修改 `GET /v1/docs/{id}` 使用 `KnowledgeDocDetailOut`
   - 新增 `GET /v1/docs/{id}/versions/{version}` 获取特定版本

3. **增强 Service** — 在 `doc_service.py` 中：
   - 新增 `get_version()` 方法

4. **补测试**

## 4. 实现约束

1. **不修改已有 KnowledgeDocOut** — 列表端点仍用轻量 schema，避免 N+1 查询
2. **只在详情端点用 DetailOut** — 包含 versions 和 source_refs 的重 schema 只用于 `GET /v1/docs/{id}`
3. **复用 selectin 关系** — KnowledgeDoc.versions 和 DocVersion.source_refs 已配置 lazy="selectin"，直接利用
4. **不改模型层** — 数据库表和关系不变
5. **不新建服务** — 在现有 doc_service 中新增方法
