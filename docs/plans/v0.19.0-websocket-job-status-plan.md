# v0.19.0 任务状态 WebSocket 推送 — 实施计划

## 1. 当前代码现状理解

### 已有能力
- GET /v1/jobs/{id} 轮询任务状态
- Worker 中 _update_job_running / _update_job_completed / _update_job_failed 更新状态
- Redis 已部署（docker-compose 中有 redis 服务）

### 缺失环节
- 客户端只能轮询，没有实时推送
- Worker 状态变更不通知 API 层

---

## 2. 本轮实施计划

### 目标
1. Worker 任务状态变更时，publish 事件到 Redis channel
2. API 新增 WebSocket 端点 `WS /v1/ws/jobs/{project_id}`
3. WebSocket handler subscribe Redis channel，推送给已连接客户端

### 事件格式
```json
{
  "event": "job_status_changed",
  "job_id": "uuid",
  "status": "running|completed|failed",
  "job_type": "ingest|architecture_draft|kb_generate|incremental",
  "error_message": null,
  "timestamp": "2026-03-18T12:00:00Z"
}
```

### 认证
- WebSocket 连接时通过 query parameter 传 token: `ws://host/v1/ws/jobs/{project_id}?token=xxx`
- 服务端验证 JWT，确认用户属于该 project 的 tenant

## 4. 实现约束

1. **Redis Pub/Sub 仅用于通知** — 不存储历史事件，错过就错过
2. **WebSocket 连接需认证** — 未认证连接直接关闭
3. **每个 project 一个 channel** — channel 名: `job_events:{project_id}`
4. **Worker 发布事件用独立 Redis 连接** — 不影响 Celery broker
