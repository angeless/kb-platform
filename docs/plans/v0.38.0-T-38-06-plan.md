## 一、当前代码现状理解

### 1.1 edit/page.tsx 现状

- 加载时从 API 获取文档内容，存入 `content` state
- 无 dirty 标记：用户修改后直接关闭页面，内容丢失无任何提示
- 保存成功后 `router.push()` 跳转回文档详情页
- 无 `beforeunload` 事件监听
- 无路由离开拦截

### 1.2 关键 state

- `content`: 编辑区文本（textarea）
- `reason`: 变更原因
- `saving`: 保存中状态
- `error`: 错误信息
- `isLoading`: 加载状态

## 二、本轮实施计划

### 2.1 添加 dirty 标记

1. 新增 `initialContent` ref（useRef）保存加载时的原始内容
2. 用 `content !== initialContent.current` 判断是否有未保存更改（isDirty）
3. 保存成功后更新 `initialContent.current = content`（清除 dirty）

### 2.2 beforeunload 事件

1. useEffect 注册 `beforeunload` 事件监听
2. 当 isDirty 时设置 `event.preventDefault()` 和 `event.returnValue = ""`
3. 浏览器会显示原生"确认离开"弹窗
4. 在 cleanup 中移除监听器

### 2.3 不使用 beforePopState

Next.js App Router（app/ 目录）不支持 `beforePopState`（这是 Pages Router 的 API）。
替代方案：仅依赖 `beforeunload`，它可以拦截关闭标签页、刷新、和浏览器后退操作。
对于 SPA 内部导航（如点击侧边栏 Link），无法通过 beforeunload 拦截，但这是 Next.js App Router 的已知限制。

## 四、实现约束

1. 只使用 `beforeunload` 事件，不依赖 Pages Router API
2. dirty 判断基于 content 与初始值比较，不包括 reason 字段
3. 不引入新依赖
4. 保存成功后清除 dirty 标记（避免保存后跳转时弹窗）
