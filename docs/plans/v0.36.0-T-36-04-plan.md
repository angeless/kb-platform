## 一、当前代码现状理解

### publish() 方法（doc_service.py:217-228）
当前代码**已有** `if doc.status != "reviewing"` 校验，但：
- 错误码使用 `DOC_ALREADY_PUBLISHED`，语义不精确（状态不对 ≠ 已发布）
- 开发计划要求使用 `DOC_STATUS_INVALID` 错误码
- 开发计划要求错误消息更明确：`"文档当前状态不允许发布，必须先进入审核状态"`

### 状态流转表（已实现）
- draft → reviewing（review()）✅ 有校验
- reviewing → published（publish()）✅ 有校验
- reviewing → draft（reject()）✅ 有校验
- draft → draft（update_content()）✅ 有校验

### 其他状态方法的错误码
- `update_content()`: 使用 `DOC_ALREADY_PUBLISHED` → 应改为 `DOC_STATUS_INVALID`
- `reject()`: 使用 `DOC_ALREADY_PUBLISHED` → 应改为 `DOC_STATUS_INVALID`
- `review()`: 使用 `DOC_ALREADY_PUBLISHED` → 应改为 `DOC_STATUS_INVALID`

---

## 二、本轮实施计划

1. 在 `ErrorCode` 中添加 `DOC_STATUS_INVALID` 错误码
2. 将 `publish()`/`review()`/`reject()`/`update_content()` 中的状态校验错误码统一改为 `DOC_STATUS_INVALID`
3. 更新错误消息为更精确的描述
4. 补充完整的状态流转测试

### 不做什么
- 不修改状态校验逻辑本身（已正确）
- 不修改 router 层
- 不修改前端
