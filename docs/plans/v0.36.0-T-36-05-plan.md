## 一、当前代码现状理解

### user_service.py

- `invite(email, role)` — 无 operator_role 参数，不校验目标角色是否高于操作者
- `update(user_id, **kwargs)` — 无 operator_role 参数，如 kwargs 中有 role 字段也不校验
- `delete(user_id)` — 不在本任务范围

### users.py (router)

- `invite_user()` — 使用 `require_role("tenant_admin")` 做最低权限检查，获取 `_user: User`，但不将 `_user.role` 传入 service
- `update_user()` — 同上，不传入操作者角色
- 两个端点都已有 `_user` 变量（当前操作者），可以直接获取 `.role`

### ROLE_HIERARCHY (deps.py:72-80)

已定义 6 级角色层级：
- viewer: 0, editor: 1, reviewer: 2, project_admin: 3, tenant_admin: 4, admin: 4, platform_admin: 5

### ForbiddenException (exceptions.py:36-40)

- 默认使用 `AUTH_INSUFFICIENT_ROLE` 错误码
- 默认消息 `"权限不足"`
- status_code = 403

### 漏洞描述

当前 tenant_admin 可以邀请 platform_admin 角色的用户，或将已有用户角色提升为 platform_admin。RBAC 只在 router 层校验"是否有权限调用此端点"，不校验"目标角色是否超出操作者权限范围"。

---

## 二、本轮实施计划

1. 在 `user_service.py` 的 `invite()` 方法增加 `operator_role: str` 参数
2. 导入 `ROLE_HIERARCHY` 和 `ForbiddenException`
3. 在 `invite()` 中校验 `ROLE_HIERARCHY[target_role] <= ROLE_HIERARCHY[operator_role]`
4. 在 `update()` 方法增加 `operator_role: str` 参数
5. 在 `update()` 中，如果 kwargs 包含 `role` 字段，校验目标角色不高于操作者角色
6. 在 `users.py` router 中，将 `_user.role` 传入 service 的 invite/update 调用
7. 编写测试覆盖所有验收场景
