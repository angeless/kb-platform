## 一、当前代码现状理解

### 1.1 url_fetcher.py 现状

- 文件: `services/api/app/utils/url_fetcher.py`
- `_BLOCKED_NETWORKS` 列表（第 20-29 行）已包含 8 个网段封锁：
  - `10.0.0.0/8` — 私有 A 类
  - `172.16.0.0/12` — 私有 B 类
  - `192.168.0.0/16` — 私有 C 类
  - `127.0.0.0/8` — 回环
  - `169.254.0.0/16` — 链路本地
  - `::1/128` — IPv6 回环
  - `fc00::/7` — IPv6 唯一本地
  - `fe80::/10` — IPv6 链路本地
- `validate_url()` 函数解析 hostname 为 IP 后逐一比对黑名单
- **缺陷**: 未封锁 `0.0.0.0/32` 和 `::/128`

### 1.2 安全影响

- `0.0.0.0` 在 Linux/macOS 上指代本机所有接口，`http://0.0.0.0:8080` 可访问本地服务
- `::` 是 IPv6 未指定地址，某些环境下可访问本地服务
- 攻击者可利用这两个地址绕过现有 SSRF 封锁

### 1.3 已有测试现状

- `test_assets.py` 中有 `test_import_url_ssrf_private_ip` 测试，验证 `192.168.1.1` 被封锁
- 无独立的 url_fetcher 单元测试文件

## 二、本轮实施计划

### 2.1 修改目标

在 `_BLOCKED_NETWORKS` 列表中添加 `0.0.0.0/32` 和 `::/128`。

### 2.2 具体步骤

1. **修改 `url_fetcher.py`**: 在 `_BLOCKED_NETWORKS` 列表中追加两项
2. **新增测试文件** `test_url_fetcher.py`: 覆盖 `validate_url()` 的各种场景，包括新增的封锁地址
