## 一、当前代码现状理解

### 1.1 后端 auth.py 现状

- `POST /v1/auth/login`：调用 `AuthService.login()`，返回 `DataResponse(data={access_token, refresh_token, token_type})`
- `POST /v1/auth/register`：调用 `AuthService.register()`，返回 `DataResponse(data={tenant_id, user_id, email})`（**不返回 token**）
- `POST /v1/auth/refresh`：调用 `AuthService.refresh()`，返回 `DataResponse(data={access_token, token_type})`
- **无 logout 端点**
- **响应中不设置 cookie**

### 1.2 后端 deps.py 现状

- `get_current_user()` 只从 `Authorization: Bearer <token>` header 读取 token
- 使用 `Header(...)` 强制要求 authorization header（缺少则 422）
- **不支持从 cookie 读取 token**

### 1.3 后端 CORS 现状 (main.py)

- `allow_credentials=True` ✅ 已配置
- `allow_origins` 从 `settings.cors_origins` 读取

### 1.4 前端 api.ts 现状

- `getToken()` 从 localStorage 读取 access_token
- `request()` 手动设置 `Authorization: Bearer` header
- `refreshAccessToken()` 用 localStorage 的 refresh_token 调用 refresh 端点
- fetch 调用**未设置 `credentials: "include"`**

### 1.5 前端 auth-store.ts 现状

- `login()` / `register()` 将 access_token 和 refresh_token 存入 localStorage
- `logout()` 清除 localStorage
- `checkAuth()` 从 localStorage 解码 JWT

### 1.6 Settings 现状

- `access_token_expire_minutes: int = 30`
- `refresh_token_expire_days: int = 7`

## 二、本轮实施计划

### 2.1 后端 auth.py 修改

1. `login` 端点：在返回 DataResponse 的同时，设置 httpOnly cookie
   - `access_token` cookie：HttpOnly=True, Secure=True, SameSite=Lax, Path=/, Max-Age=1800
   - `refresh_token` cookie：HttpOnly=True, Secure=True, SameSite=Lax, Path=/v1/auth, Max-Age=604800
2. `register` 端点：注册成功后不返回 token（维持现状），不设置 cookie
   - 原因：当前 register 的 AuthService.register() 不返回 token，不改 service 层
3. `refresh` 端点：在返回新 access_token 的同时，设置新的 access_token cookie
4. **新增** `POST /v1/auth/logout` 端点：
   - 清除 access_token 和 refresh_token cookie（Max-Age=0）
   - 返回 204 No Content

### 2.2 后端 deps.py 修改

1. `get_current_user()` 参数改为 Optional authorization header
2. 读取顺序：优先 Authorization header → 其次 `request.cookies["access_token"]`
3. 两者都没有时抛出 UnauthorizedException

### 2.3 前端 api.ts 修改

1. 所有 fetch 调用添加 `credentials: "include"`（让浏览器自动发送 cookie）
2. `refreshAccessToken()` 也添加 `credentials: "include"`（refresh cookie 随请求发送）
3. 移除 `getToken()` 方法和手动 Authorization header 设置
4. 移除 `refreshAccessToken()` 中的 localStorage 操作（cookie 由后端管理）
5. 401 拦截逻辑保留但简化：刷新时直接 POST `/v1/auth/refresh`，不传 body（从 cookie 读取）

**待确认**：refresh 端点当前需要 body `{refresh_token}`。改为从 cookie 读取需要同时改后端。为保持**向后兼容**（API 调用者仍可用 body 传 refresh_token），后端 refresh 端点改为：优先从 body 读，如无则从 cookie 读。

### 2.4 前端 auth-store.ts 修改

1. `login()` / `register()`：不再存储 token 到 localStorage
2. `logout()`：调用 `POST /v1/auth/logout`（由后端清除 cookie），清除 localStorage 残留
3. `checkAuth()`：改为调用 `GET /v1/auth/me`（新端点）或保留从 cookie 解码
   - **问题**：httpOnly cookie 前端 JS 无法读取，所以无法再用 atob 解码
   - **方案**：login 响应体仍返回 user 信息，前端从响应体存入 zustand；checkAuth 改为调用后端接口获取用户信息
   - **新增端点** `GET /v1/auth/me`：从 token 解码返回 user 信息

### 2.5 新增 GET /v1/auth/me 端点

- 依赖 `get_current_user`
- 返回 `{id, email, role, tenant_id}`
- 用于页面刷新时恢复用户状态（替代前端 JWT 解码）

## 四、实现约束

1. **向后兼容**：Authorization header 认证方式保留，API 调用者（非浏览器）仍可用 Bearer token
2. **refresh 端点向后兼容**：body 中有 refresh_token 则优先用 body 的，无则从 cookie 读
3. **Secure 标志**：开发环境 (localhost) Secure=False，生产环境 Secure=True。通过检查 settings 或环境变量控制
4. **cookie path**：access_token 的 Path=/（所有路径需要），refresh_token 的 Path=/v1/auth（只有 auth 路径需要）
5. **不引入新依赖**：FastAPI 原生 Response.set_cookie() 即可
6. **register 不设置 cookie**：维持当前 register 不返回 token 的行为（若后续需要注册即登录，应作为独立任务处理）
