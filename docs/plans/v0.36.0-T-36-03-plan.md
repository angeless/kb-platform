## 一、当前代码现状理解

### assign_node() 方法（doc_service.py:86-103）
```python
async def assign_node(self, doc_id: uuid.UUID, node_id: uuid.UUID) -> KnowledgeDoc:
    doc = await self.get(doc_id)  # ✅ 验证 doc 属于当前租户
    q = select(ArchitectureNode).where(ArchitectureNode.id == node_id)  # ❌ 只检查 node 是否存在
    result = await self.db.execute(q)
    node = result.scalar_one_or_none()
    if node is None:
        raise NotFoundException(...)
    doc.node_id = node_id
```

### 问题
- 查询 `ArchitectureNode` 时**没有验证**该节点所属的 Architecture 是否属于 doc 的同一 project
- 关系链：`ArchitectureNode.architecture_id → Architecture.project_id`
- 攻击者可以将自己的文档分配到其他租户/项目的架构节点

### 数据模型
- `Architecture` 有 `project_id` 字段
- `ArchitectureNode` 有 `architecture_id` 外键指向 `Architecture`
- `KnowledgeDoc` 有 `project_id` 字段

---

## 二、本轮实施计划

### 修改策略
在 `assign_node()` 中查询 `ArchitectureNode` 时，JOIN `Architecture` 表并验证 `Architecture.project_id == doc.project_id`。

### 具体步骤
1. 修改 node 查询：JOIN architecture，增加 `Architecture.project_id == doc.project_id` 条件
2. 错误码改为更精确的 `ARCH_NODE_NOT_FOUND`
3. 错误消息改为 `"节点不存在或不属于当前项目"`
