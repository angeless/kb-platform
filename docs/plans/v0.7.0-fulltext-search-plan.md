# v0.7.0 基础全文检索 — 实施计划

## 1. 当前代码现状理解

### 已有能力
- `KnowledgeDocVersion.content_md` 存储 Markdown 正文（Text 字段）
- `AssetChunk.content_text` 存储原始资料片段（Text 字段）
- `KnowledgeDoc.title` 存储文档标题
- 所有数据通过 `project_id` 关联，支持按项目范围搜索

### 缺失环节
- 没有搜索端点
- 没有 PostgreSQL 全文索引
- PRD 定义 `POST /v1/search/text`（doc 05, section 4.6），未实现

### 技术决策
- 使用 PostgreSQL 内置全文检索（`to_tsvector` / `to_tsquery`），不引入 Elasticsearch
- 搜索范围：知识文档正文（KnowledgeDocVersion.content_md）+ 文档标题（KnowledgeDoc.title）
- 本阶段只做 `POST /v1/search/text`，语义检索和混合检索留待后续

---

## 2. 本轮实施计划

### 实现方案
1. **新增 search schema** — 定义搜索请求和搜索结果的 Pydantic schema
2. **新增 search service** — 使用 PostgreSQL `ILIKE` 进行基础文本匹配（简单可靠），在知识文档的 title 和 content_md 中搜索
3. **新增 search router** — `POST /v1/search/text` 端点
4. **注册 router** — 在 main.py 中注册
5. **补测试**

### 搜索逻辑
```
POST /v1/search/text
Body: { "project_id": "...", "query": "退款", "page": 1, "page_size": 20 }

→ 在 KnowledgeDoc JOIN KnowledgeDocVersion 中搜索
→ 匹配 title ILIKE '%退款%' OR content_md ILIKE '%退款%'
→ 返回匹配的文档列表（含匹配片段摘要）
```

### 为什么用 ILIKE 而不是 tsvector
- `tsvector` 需要中文分词插件（zhparser/pg_jieba），增加部署复杂度
- Sprint 2 要求"基础全文检索"，ILIKE 足够满足
- 后续可透明升级为 tsvector 或 Elasticsearch，不影响 API 契约

## 4. 实现约束

1. **不新增数据库表** — 搜索基于已有 KnowledgeDoc + KnowledgeDocVersion 表
2. **不引入外部依赖** — 不装 Elasticsearch、不装中文分词插件
3. **租户隔离** — 搜索必须限定在当前租户的项目内
4. **分页** — 复用现有 ListResponse 分页模式
5. **不修改已有代码逻辑** — 只新增文件 + main.py 注册
