## 1. 当前代码现状理解

### 1.1 API 层

| 项目 | 现状 |
|------|------|
| 应用入口 | `services/api/app/main.py` — `create_app()` 工厂函数 |
| 路由前缀 | 大部分 router 使用 `/v1/` 前缀（auth, projects, jobs, assets, docs, conflicts, users, search, ingestion, audit），部分 router 内部定义路径（architectures, model_providers, ws, export） |
| 中间件 | 2 个：`RequestIdMiddleware` + `RateLimitMiddleware` |
| CORS | 未配置 |
| 健康检查 | `/healthz`（liveness）+ `/readyz`（DB SELECT 1） |
| 日志 | Python stdlib logging，纯文本，各模块独立初始化 |
| Prometheus | 无 |
| OpenAPI | FastAPI 自动生成，无 summary/description/error responses 增强 |
| CI/CD | 无 GitHub Actions 工作流 |
| 优雅停机 | 无 shutdown hook |

### 1.2 配置层

- `packages/shared-config/shared_config/settings.py` — pydantic-settings `Settings` 类
- 已有 `log_level` 字段（默认 INFO）
- 无 `cors_origins` 字段

### 1.3 基础设施

- `docker-compose.yml` — postgres(pgvector), redis, minio, api, 3 workers
- 无 `docker-compose.monitoring.yml`
- 无 `.github/workflows/` 目录

## 2. 本轮实施计划

按照 PRD 定义的 10 个任务（T-35-01 ~ T-35-10），按依赖关系分批执行：

| 任务编号 | 任务名称 | 依赖 | 优先级 |
|----------|----------|------|--------|
| T-35-01 | API 版本端点 + CORS 策略 | 无 | P0 |
| T-35-02 | 深度健康检查 | 无 | P0 |
| T-35-03 | 结构化日志 | 无 | P0 |
| T-35-04 | Prometheus 指标暴露 | 无 | P1 |
| T-35-05 | Grafana 仪表盘 | T-35-04 | P1 |
| T-35-06 | CI/CD Pipeline | 无 | P1 |
| T-35-07 | 优雅停机处理 | 无 | P1 |
| T-35-08 | OpenAPI 规范完善 | 无 | P2 |
| T-35-09 | 运维文档 | T-35-01~08 | P2 |

> 注：PRD 编号 T-35-01（API 版本化）和 T-35-02（CORS）合并为本计划 T-35-01，
> 因为现有代码已有 `/v1/` 前缀，T-35-01 仅需添加 `/api/versions` 端点和 CORS 配置。
> 后续 PRD 编号顺延：PRD T-35-03 → 本计划 T-35-02，以此类推。

### 执行顺序

每次只推进一个任务，独立闭环：

1. **T-35-01**: `/api/versions` 端点 + CORS 中间件配置
2. **T-35-02**: 深度健康检查 `/api/health/ready`（PG + Redis + MinIO）
3. **T-35-03**: 结构化 JSON 日志（python-json-logger）
4. **T-35-04**: Prometheus 指标暴露（prometheus-client + /metrics 端点）
5. **T-35-05**: Grafana 仪表盘（docker-compose.monitoring.yml + 预配置 dashboards）
6. **T-35-06**: CI/CD（GitHub Actions ci.yml + build.yml）
7. **T-35-07**: 优雅停机（shutdown hook + Celery 参数 + Docker stop_grace_period）
8. **T-35-08**: OpenAPI 规范完善（端点 summary/description/responses 增强）
9. **T-35-09**: 运维文档（部署指南 + Runbook + 升级指南）

## 4. 实现约束

1. **不改变现有 API 契约** — 所有现有端点路径、请求体、响应体保持不变
2. **不改变数据库 schema** — v0.35 无迁移脚本
3. **不修改业务逻辑** — 仅增加运维/可观测性/文档能力
4. **中间件添加顺序** — CORS 必须在最外层，Prometheus/日志在 RequestId 之后
5. **向后兼容** — `/healthz` 和 `/readyz` 保留不变，新增 `/api/health/ready`
6. **配置驱动** — 所有新功能通过环境变量控制，有合理默认值
7. **不推倒重写** — 在现有代码基础上增量添加，不重构已验证通过的链路
