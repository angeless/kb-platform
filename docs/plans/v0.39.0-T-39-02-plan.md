## 一、当前代码现状理解

### 1.1 4 个 Dockerfile 现状

所有 4 个 Dockerfile 都以 root 用户运行：
- 无 `addgroup` / `adduser` 指令
- 无 `USER` 指令
- WORKDIR 均为 `/app`
- 共享包安装在 `/packages/`

### 1.2 各 Dockerfile 差异

| Dockerfile | 特殊点 |
|-----------|--------|
| api.Dockerfile | 有 apt-get 安装系统包；有 ENTRYPOINT 脚本；EXPOSE 8080 |
| ingestion-worker | COPY .env.example；CMD celery |
| pipeline-worker | CMD celery -Q pipeline |
| ai-orchestrator | COPY .env.example；CMD celery |

---

## 二、本轮实施计划

在每个 Dockerfile 中：
1. 在所有 `RUN pip install` 和 `COPY` 完成后添加用户创建
2. 确保 `/app` 和 `/packages` 目录对 appuser 可读
3. 在 CMD/ENTRYPOINT 之前设置 `USER appuser`

### 特殊处理
- api.Dockerfile 有 entrypoint.sh，需确保 appuser 可执行
- pip install 以 `-e` 模式安装（editable），需确保 .egg-info 目录可写——但由于 `-e` 安装在 root 阶段完成，运行时不需要写入

## 四、实现约束

1. 用户/组名统一为 `appuser` / `appgroup`
2. 在所有文件安装/复制完成后再创建用户和切换
3. 不修改 docker-compose.yml
4. 不改变功能行为，只改变运行时用户
