# v0.12.0 权限控制完善 — 实施计划

## 1. 当前代码现状理解

### 已有能力
- JWT 认证完整（`get_current_user` 从 token 中提取用户，查 DB 确认存在）
- 租户隔离完整（`get_tenant_id` 自动注入 tenant_id，所有查询带 tenant 过滤）
- User 模型已有 `role` 字段（支持 6 种角色）
- 用户管理已有（invite/update_role/disable）

### 缺失环节
- **没有角色授权检查** — 所有已认证用户都能执行所有操作
- 需要一个 `require_role` 依赖注入函数，在 router 层强制校验角色
- 需求文档 08 定义了 6 个角色的操作边界

### 需求定义（08-权限、多租户与安全规范 section 2）
| 角色 | 能力 |
|------|------|
| platform_admin | 平台级配置、租户状态、系统监控（不浏览租户私有知识） |
| tenant_admin | 管理本租户用户、项目、模型配置、权限策略 |
| project_admin | 管理本项目架构、文档、审核流、接入资料 |
| editor | 上传、编辑、提交审核 |
| reviewer | 审核文档、冲突记录、架构变更 |
| viewer | 查看已发布内容 |

## 2. 本轮实施计划

### 目标
1. 新建 `require_role()` 依赖注入工厂函数
2. 在各 router 端点上添加角色检查
3. 返回 403 Forbidden（含错误码 `AUTH_FORBIDDEN`）当角色不足时
4. 补充测试验证 viewer 无法执行写操作

### 权限矩阵
| 端点 | 最低角色 |
|------|----------|
| GET /v1/projects, /v1/docs, /v1/assets 等查询端点 | viewer |
| POST /v1/assets/upload, /import-url, /import-archive | editor |
| POST /v1/docs/{id}/assign-node | editor |
| POST /v1/docs/{id}/review | reviewer |
| POST /v1/docs/{id}/publish | project_admin |
| POST /v1/architectures/{id}/publish | project_admin |
| POST /v1/architectures/{id}/nodes, PATCH nodes | project_admin |
| POST /v1/conflicts/{id}/resolve | reviewer |
| POST /v1/jobs | editor |
| POST /v1/model-providers, /model-routes | tenant_admin |
| POST /v1/users/invite, PATCH /v1/users/{id} | tenant_admin |
| DELETE /v1/projects/{id} | tenant_admin |
| GET /v1/audit-logs | tenant_admin |

### 角色层级
`platform_admin > tenant_admin > project_admin > reviewer > editor > viewer`

高级角色自动拥有低级角色的权限（即 tenant_admin 也可以上传文件）。

### 设计要点
- `require_role("editor")` 返回一个 FastAPI Depends，检查 `current_user.role` 是否 >= 要求的角色
- 角色比较基于层级数值（viewer=0, editor=1, reviewer=2, project_admin=3, tenant_admin=4, platform_admin=5）
- 不通过时抛出 `ForbiddenException`（403），错误码 `AUTH_FORBIDDEN`

## 4. 实现约束

1. **只在 router 层加角色检查** — 不修改 service 层
2. **不改已有方法签名** — 只通过 Depends 参数添加
3. **高角色包含低角色权限** — 层级比较，不硬编码列表
4. **GET 端点不加角色限制**（viewer 即可）— 只给写操作加限制
5. **不破坏现有测试** — 现有测试使用的 auth_headers 对应 tenant_admin 角色，应全部通过
