## 一、当前代码现状理解

### 1.1 搜索服务现状

- `services/api/app/services/search_service.py` 中的 `text_search()` 方法是全文搜索入口
- 当前流程：
  1. `_build_tsquery(query)` 清洗 tsquery 操作符
  2. 如果清洗后不为空，尝试 tsvector 搜索
  3. 如果 tsvector 无结果或清洗后为空，回退到 `_ilike_search()`
- **问题所在**：当用户传入全空白字符串（如 `"   "`、`"\t\n"`），Pydantic `min_length=1` 校验通过（长度 >= 1），但 `_build_tsquery()` 返回空串，流程直接进入 `_ilike_search()`，ILIKE pattern 变为 `%   %`，可能返回意外结果
- 正确行为：全空白查询应直接返回空结果，不执行任何数据库查询

### 1.2 Schema 现状

- `packages/shared-schemas/shared_schemas/search.py`：`query: str = Field(..., min_length=1, max_length=500)`
- `min_length=1` 不阻止全空白字符串

### 1.3 已有测试现状

- `test_search.py`：有 `test_search_empty_query_rejected` 测试空字符串 `""` 返回 422
- `test_search_utils.py`：有 `test_only_whitespace_returns_empty` 验证 `_sanitize_tsquery_input("   ")` 返回 `""`
- **缺失测试**：没有测试全空白字符串通过 API 时的行为

## 二、本轮实施计划

### 2.1 修改目标

在 `text_search()` 入口处对 `query` 执行 `strip()`，如果 strip 后为空字符串，直接返回 `([], 0)`，不执行数据库查询。

### 2.2 具体步骤

1. **修改 `search_service.py` 的 `text_search()` 方法**：
   - 在 `_verify_project()` 之后、`_build_tsquery()` 之前
   - 添加 `query = query.strip()`
   - 添加 `if not query: return [], 0`

2. **补充测试**：
   - 在 `test_search_utils.py` 中添加对 `_build_tsquery` 纯制表符/换行的测试
   - 在 `test_search.py` 中添加 API 级测试：全空白查询返回 200 + 空结果
