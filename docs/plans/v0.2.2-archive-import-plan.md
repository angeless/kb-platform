# V0.2.2 实施计划：压缩包导入端点

## 当前代码现状理解

### 已有能力
- `POST /v1/assets/upload` — 单文件上传，含类型/大小校验、SHA-256 去重、MinIO 存储
- `POST /v1/assets/import-url` — URL 抓取导入，含 SSRF 防护
- `ImportArchiveRequest` schema 已定义（shared_schemas/asset.py），含 project_id
- `AssetService.upload()` 可处理单个文件
- `storage.py` 的 `is_allowed_file()` 可校验文件扩展名
- 压缩包扩展名（.zip, .tar, .gz, .7z, .rar）已在白名单内

### 差距
- 无压缩包导入端点
- 无解压逻辑

## 本轮实施计划

### 目标
实现 `POST /v1/assets/import-archive` 端点。接收压缩包文件，解压，将包内每个合法文件分别创建为独立的 Asset 记录并存入 MinIO。

### 实现方案
1. 修改 `asset_service.py` — 新增 `import_archive()` 方法，解压 zip，逐个调用现有 upload 逻辑
2. 修改 `assets.py` 路由 — 新增 `POST /v1/assets/import-archive` 端点
3. 补充测试

### 设计决策
- **仅支持 ZIP 格式**（Python 标准库 zipfile）。tar/7z/rar 后续扩展
- **跳过不支持的文件类型**（不报错，返回成功导入数量）
- **跳过重复哈希文件**（不报错，计入跳过数量）
- **返回格式**：`{imported: N, skipped: M, errors: [...]}`

## 实现约束
1. 不破坏已有 68 个测试
2. 不修改 shared-models / shared-config
3. 仅用 Python 标准库 zipfile（不引入新依赖）
4. 解压在内存中完成（不写临时文件到磁盘）
5. 单个压缩包内文件数上限 100（防止 zip bomb）

## 测试要求
- test_import_archive_success：上传含 2 个文件的 zip，验证创建 2 个 asset
- test_import_archive_skips_unsupported：zip 内含 .exe 文件，应被跳过
- test_import_archive_empty_zip：空 zip 返回 imported=0
- 回归：全部 68 个已有测试通过
