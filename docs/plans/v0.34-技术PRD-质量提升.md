# v0.34 技术 PRD — 质量提升

> **版本号**: v0.34.0
> **基线版本**: v0.33.0（端到端打通与安全加固完成后）
> **发布目标**: 提升搜索性能、前端工程质量、测试覆盖率，使系统从"能跑"进入"好用"阶段
> **预估工期**: 3-4 周（15-20 个工作日）
> **PRD 编写日期**: 2026-03-19
> **前置条件**: v0.33 全部验收通过

---

## 一、版本定位

v0.34 是一个**质量提升版本**。v0.33 打通了端到端闭环后，v0.34 聚焦于三件事：

1. **搜索体验**: 向量搜索从内存暴力计算升级为 pgvector，全文搜索从 ILIKE 升级为 GIN 索引
2. **前端工程化**: 引入 React Query 统一数据获取、引入 Vitest 测试框架
3. **质量保障**: 租户隔离验证、ASR 线程安全、批量操作错误结构化

本版本完成后，搜索性能提升 10~50 倍，前端代码进入可测试状态，租户隔离获得自动化验证。

## 三、本版本明确不做的事

1. **不引入 Elasticsearch**（全文搜索使用 PostgreSQL GIN 足够）
2. **不引入外部向量数据库**（pgvector 扩展在 PostgreSQL 内即可）
3. **不做前端国际化 (i18n)**
4. **不做 CI/CD 搭建**（推迟到 v0.35）
5. **不做 API 版本化**（推迟到 v0.35）
6. **不新增用户可见功能页面**
7. **不重构后端架构**（Service 基类提取等推迟）
8. **不做前端无障碍(a11y)改进**

---

## 四、实现约束

1. **pgvector 兼容性**: 使用 pgvector 0.7+ 的 `vector` 类型和 `<=>` 余弦距离运算符。PostgreSQL 版本需 ≥ 15。
2. **数据迁移**: DocEmbedding 表从 JSONB 存储迁移到 vector 类型，需编写 Alembic 迁移脚本，包含数据转换。新增 `embedding_vec vector(1536)` 列，保留旧 `embedding` 列一个版本。
3. **搜索向后兼容**: 引入 GIN 索引和 tsvector 时，API 响应格式不变。搜索排序仍支持 `created_at` 和 `relevance` 两种。
4. **前端向后兼容**: 引入 React Query 时，API 响应格式不变。旧的 fetch 逻辑逐页面替换，不一次性全改。
5. **测试不 mock 数据库**: 租户隔离测试必须使用真实数据库（测试容器或 docker-compose 中的 PG）。

### 任务 T-34-02: DocEmbedding 模型迁移至 vector 类型

**目标**: 将 `DocEmbedding.embedding` 字段从 `JSONB` 迁移为 pgvector 的 `vector(1536)` 类型。

**输入**:
- `packages/shared-models/shared_models/models.py` 中 DocEmbedding 定义
- 现有 JSONB 格式: `[0.1, 0.2, ..., 0.3]`（1536 维）
- 现有 DocEmbedding 表结构（待迁移）

**输出**:
- DocEmbedding 模型新增 `embedding_vec: Vector(1536)` 字段（使用 `pgvector.sqlalchemy.Vector`）
- Alembic 迁移脚本包含数据转换:
  ```sql
  ALTER TABLE doc_embeddings ADD COLUMN embedding_vec vector(1536);
  UPDATE doc_embeddings SET embedding_vec = embedding::vector(1536) WHERE embedding IS NOT NULL;
  ```
- 旧 JSONB 字段 `embedding` 保留一个版本后再删

**数据库变更详情**:

**DocEmbedding 表新增字段**:
```
字段名: embedding_vec
数据类型: vector(1536)
Nullable: YES (初期为 YES，在回填数据后考虑是否转为 NOT NULL)
默认值: NULL
描述: PostgreSQL pgvector 存储的向量表示，用于语义搜索
```

**规则与边界**:
- 新增 `embedding_vec` 字段（vector 类型），不立即删除旧 `embedding` 字段
- 迁移脚本必须处理异常数据：
  - embedding 为 null 的行 → embedding_vec 设为 null
  - embedding 长度不等于 1536 的行 → 记录 warning，跳过该行
  - embedding 包含 NaN/Inf 的行 → 记录 warning，跳过
- 不修改 EmbeddingService 的公开接口签名

**验收标准**:
- [ ] 迁移后 `\d doc_embeddings` 显示新列 `embedding_vec vector(1536)`
- [ ] 已有数据（如果存在）正确转换到新列
- [ ] 异常数据（null/长度不符）被正确处理，迁移不阻断
- [ ] 旧 `embedding` 列仍存在，数据保持不变
- [ ] 重新运行迁移脚本为幂等（不报错）

**涉及文件**:
| 文件 | 操作 | 说明 |
|------|------|------|
| `packages/shared-models/shared_models/models.py` | 修改 | 添加 embedding_vec: Vector(1536) 字段 |

### 任务 T-34-03: EmbeddingService 切换到 pgvector 查询

**目标**: `semantic_search` 方法从 Python 内存计算切换为 SQL 向量距离查询，性能从秒级降至百毫秒级。

**输入**:
- `services/api/app/services/embedding_service.py`
- 当前逻辑:
  ```python
  # 伪代码
  embeddings = session.query(DocEmbedding).all()  # 加载所有向量
  similarities = [cosine_similarity(query_vec, vec) for vec in embeddings]
  results = sorted(zip(embeddings, similarities), key=...)[:top_k]
  ```

**输出**:
- `semantic_search` 使用 SQL:
  ```python
  SELECT ... FROM doc_embeddings
  ORDER BY embedding_vec <=> :query_vec
  LIMIT :top_k
  ```
- 删除 `cosine_similarity` Python 函数（由 pgvector 提供）
- `embed_doc` 同时写入 `embedding_vec` 字段（写双列直到 T-35 删除旧列）

**规则与边界**:
- `embed_fn` 接口不变（仍返回 `list[float]`，维度 1536）
- 向量维度固定 1536（text-embedding-3-small 标准）
- 如果项目下无 embedding，返回空列表（与当前行为一致）
- 可选：添加 IVFFlat 索引加速，但不做索引调优（推迟到 v0.36）
- 余弦距离排序（`<=>` 操作符）

**验收标准**:
- [ ] 搜索结果质量与旧实现一致（同一查询返回相同 top-10 文档，可允许顺序微调）
- [ ] 1000 条向量的搜索时间 < 100ms（旧实现约 2-5 秒）
- [ ] 10000 条向量的搜索时间 < 200ms
- [ ] 无 API 响应格式变更
- [ ] 原有语义搜索测试全部通过

**涉及文件**:
| 文件 | 操作 | 说明 |
|------|------|------|
| `services/api/app/services/embedding_service.py` | 修改 | semantic_search 改用 SQL 查询；embed_doc 写入 embedding_vec |
| `services/api/tests/test_search.py` | 修改 | 适配新查询方式，性能测试 |

### 任务 T-34-04: 全文搜索升级为 PostgreSQL GIN 索引

**目标**: `SearchService.text_search` 从 `ILIKE '%keyword%'` 升级为 PostgreSQL `tsvector` + GIN 索引，性能提升 10~50 倍。

**输入**:
- `services/api/app/services/search_service.py`
- 当前使用 `ILIKE` 模糊匹配 title 和 content_md
- 当前支持中文搜索但效果不理想

**输出**:
- KnowledgeDoc 表新增 `search_vector tsvector` 列
- KnowledgeDocVersion 表新增 `search_vector tsvector` 列
- GIN 索引 on `search_vector`
- `text_search` 使用 `to_tsquery` + `@@` 操作符
- 保留 ILIKE 作为 fallback（当 tsvector 无匹配时）

**数据库变更详情**:

**KnowledgeDoc 表新增字段**:
```
字段名: search_vector
数据类型: tsvector
Nullable: YES
默认值: NULL
描述: PostgreSQL tsvector 存储的全文搜索向量，由 title 和 content_md 的中文分词组成
更新机制: 由 trigger 或手动更新脚本填充
```

**KnowledgeDocVersion 表新增字段**:
```
字段名: search_vector
数据类型: tsvector
Nullable: YES
默认值: NULL
描述: PostgreSQL tsvector 存储的全文搜索向量，由 version_content 的中文分词组成
更新机制: 由 trigger 或手动更新脚本填充
```

**GIN 索引**:
```
CREATE INDEX idx_knowledge_doc_search_vector ON knowledge_docs USING gin(search_vector);
CREATE INDEX idx_knowledge_doc_version_search_vector ON knowledge_doc_versions USING gin(search_vector);
```

**规则与边界**:
- 中文分词使用 `simple` 配置（pgvector 官方镜像内置，避免依赖 zhparser）
- 或如果可用，使用 `pg_jieba` 扩展（可选，但不强制）

**验收标准**:

### 任务 T-34-08: ASR Parser 线程安全修复

**目标**: 修复 `asr_parser.py` 中全局变量缓存 Whisper 模型的线程安全问题。防止并发任务冲突。

**输入**:
- `services/ingestion-worker/worker/parsers/asr_parser.py`
- 当前使用模块级变量缓存模型，无锁
- Celery worker 可能配置为 threads/gevent 模式

**输出**:
- 使用 `threading.Lock` 保护模型加载
- 或使用 `functools.lru_cache` 替代手动缓存

**代码示例**:
```python
import threading

_model_lock = threading.Lock()
_whisper_model = None

def _get_whisper_model():
    global _whisper_model
    if _whisper_model is None:
        with _model_lock:
            if _whisper_model is None:
                _whisper_model = whisper.load_model("base")
    return _whisper_model
```

**规则与边界**:
- 不改变解析逻辑
- 不改变返回格式
- Celery worker 默认 prefork 模式，每个进程有独立 GIL，但 `threads` 配置下需要保护

**验收标准**:
- [ ] 并发 2 个 ASR 解析任务不 crash 或死锁
- [ ] 模型只加载一次（通过 log 验证"model loaded once"消息）

### 任务 T-34-09: 批量操作错误处理结构化

**目标**: 批量操作端点（批量审核、批量发布等）的错误响应从 `str(e)` 改为结构化 JSON。对齐后端错误体系。

**输入**:
- `services/api/app/routers/docs.py` 等批量操作路由
- 当前错误格式: `{"id": "xxx", "error": "some error string"}`
- 后端有 `shared_errors.py` 定义的标准错误码

**输出**:
- 错误格式改为: `{"id": "xxx", "error_code": "DOC_NOT_FOUND", "message": "文档不存在"}`
- 与 `shared_errors` 的错误码体系对齐

**标准错误码映射表**:

| 场景 | 错误码 | HTTP 消息 |
|------|--------|----------|
| 文档不存在 | DOC_NOT_FOUND | 404 |
| 项目不存在 | PROJECT_NOT_FOUND | 404 |
| 权限不足 | PERMISSION_DENIED | 403 |
| 数据冲突 | CONFLICT | 409 |
| 操作失败 | OPERATION_FAILED | 500 |

**规则与边界**:
- 只修改批量操作端点（如 PATCH /docs/{id}/review-status 批量版本）
- 单个操作端点不变
- 成功响应格式不变（如 `{"id": "xxx", "status": "published"}` 仍是该格式）
- 不改变 HTTP status code（仍为 200，body 中含 errors 列表）

**验收标准**:
- [ ] 批量操作部分失败时，errors 数组中每项包含 `id`、`error_code` 和 `message`
- [ ] 前端批量操作页面仍能正常显示错误信息
- [ ] 现有批量操作测试通过
- [ ] 新增 2 个测试验证错误格式

**涉及文件**:
| 文件 | 操作 | 说明 |

## 六、数据库变更总结

本版本新增以下数据库字段和索引，所有变更通过 Alembic 迁移实现：

### 新增字段

**DocEmbedding 表**:
- `embedding_vec`: `vector(1536)` 类型，nullable，存储 pgvector 格式的向量

**KnowledgeDoc 表**:
- `search_vector`: `tsvector` 类型，nullable，存储全文搜索向量

**KnowledgeDocVersion 表**:
- `search_vector`: `tsvector` 类型，nullable，存储全文搜索向量

### 新增索引

```sql
CREATE INDEX idx_doc_embedding_search ON doc_embeddings USING ivfflat(embedding_vec vector_cosine_ops);
CREATE INDEX idx_knowledge_doc_search_vector ON knowledge_docs USING gin(search_vector);
CREATE INDEX idx_knowledge_doc_version_search_vector ON knowledge_doc_versions USING gin(search_vector);
```

### Alembic 迁移脚本清单

1. `xxx_add_pgvector_extension.py` — 创建 pgvector 扩展
2. `xxx_add_embedding_vec_column.py` — 添加 embedding_vec 列及数据迁移
3. `xxx_add_search_vector_columns.py` — 添加 tsvector 列及初始化

所有迁移脚本必须支持幂等执行（可重复运行）。
