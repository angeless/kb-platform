## 任务一：真实 LLM 调用的端到端流程验证

### 背景
当前 AI Orchestrator 的 LLM 调用逻辑（架构提议、文档生成、增量分类）虽然代码完整，但从未在真实 LLM 环境下做过完整端到端验证。审计发现分类降级为"全部标记为 new"的 fallback 逻辑、文档生成 fallback 为"原始文本文档"的逻辑，说明核心 AI 能力实际可能一直运行在降级模式。

### 验证内容
1. **架构提议流程**: 上传一批真实行业资料 → 触发 `propose_architecture` → 验证生成的架构是否合理（层级数、节点数、节点类型、行业识别）
2. **文档生成流程**: 基于生成的架构 → 触发 `generate_docs` → 验证每份文档是否有来源追溯、是否发生知识坍缩、是否遗漏关键信息
3. **增量分类流程**: 在已有知识库基础上 → 添加新资料 → 触发 `classify_incremental` → 验证分类结果（new/supplement/correction/conflict 比例是否合理）
4. **Prompt 质量**: 审查 prompts.py 中所有 prompt 模板，验证是否符合 `12-实施约束与不偏移开发规则.md` 中第 4 节 AI 工程约束

### 前置条件
- 需要可用的 OpenAI API Key（或兼容 API）
- 需要准备 3 套测试数据集（不同行业：科技/医疗/教育）
- 需要部署完整服务栈（含 AI Orchestrator）

### 验收标准
- [ ] 3 套数据集均成功走通完整流程（无 fallback）
- [ ] 架构提议的行业识别准确率 ≥ 80%
- [ ] 文档生成的来源追溯覆盖率 ≥ 90%
- [ ] 增量分类的准确率 ≥ 70%（与人工标注对比）
- [ ] 无知识坍缩（输出文档数量 ≥ 输入资料涉及主题数）

### 预估工时
16-24 小时（含数据准备、测试执行、结果分析）

## 任务二：性能基准测试（大数据量下的搜索和解析）

### 背景
当前系统在开发环境的小数据量下运行正常，但未做过压力测试。审计发现以下性能风险点：EmbeddingService 的 JSONB cosine similarity fallback 在 Python 中全量计算、搜索空查询可能返回全量数据、批量操作无 savepoint 导致长事务。

### 验证内容
1. **搜索性能**:
   - 全文搜索: 1 万/5 万/10 万篇文档下的 P95 响应时间
   - 语义搜索 (pgvector): 同上
   - 语义搜索 (JSONB fallback): 同上
   - 并发搜索: 50/100/200 QPS 下的成功率和延迟

2. **解析性能**:
   - 单次解析: 100 页 PDF、1 小时音频、10MB 图片的解析时间
   - 批量解析: 100 个文件同时上传后的处理时间
   - Celery worker 队列积压时的处理延迟

3. **数据库性能**:
   - 文档列表分页: 10 万篇文档下的分页查询延迟
   - 架构树查询: 1000 节点架构的树加载时间
   - 审计日志查询: 100 万条审计记录下的查询延迟

4. **资源消耗**:
   - API 服务内存占用（空载 vs 满载）
   - Worker 内存占用（解析大文件时峰值）
   - PostgreSQL 连接池使用率

### 前置条件
- 需要生成测试数据的脚本
- 需要压测工具（推荐 locust 或 k6）
- 需要接近生产规格的环境

### 验收标准
- [ ] 全文搜索 P95 < 500ms（10 万文档）
- [ ] 语义搜索 pgvector P95 < 1s（10 万文档）
- [ ] 分页查询 P95 < 200ms
- [ ] 100 QPS 并发搜索成功率 > 99%
- [ ] API 服务内存 < 1GB
- [ ] 产出完整的性能基准报告

### 预估工时
20-32 小时（含脚本开发、测试执行、分析报告）

## 任务三：安全渗透测试（部署后真实环境）

### 背景
代码审计发现了 12 个安全漏洞，v0.36-v0.39 将修复其中大部分。但代码审计无法覆盖运行时安全（如 Docker 网络配置、TLS 证书、实际 CORS 行为、cookie 设置等）。需要在真实部署环境中进行渗透测试。

### 验证内容
1. **认证安全**:
   - JWT 伪造/篡改测试
   - Token 重放攻击
   - 暴力破解防护（rate limit 实际效果）
   - 密码重置 token 可预测性

2. **授权安全**:
   - IDOR 全面扫描（所有接受 UUID 参数的端点）
   - RBAC 穿透测试（每个端点 × 每个角色）
   - 跨租户数据访问

3. **注入攻击**:
   - SQL 注入（虽然审计确认使用 ORM，仍需黑盒验证）
   - XSS（存储型 + 反射型）
   - SSRF（实际网络环境下的绕过尝试）
   - 命令注入（文件名、URL 参数）

4. **网络安全**:
   - TLS 配置检查
   - HTTP 安全头（X-Frame-Options, X-Content-Type-Options, CSP, HSTS）
   - Cookie 属性验证（HttpOnly, Secure, SameSite）
   - CORS 实际行为验证

5. **基础设施安全**:
   - Docker 容器逃逸测试
   - 服务间通信加密
   - 敏感信息扫描（环境变量、日志、错误响应）
   - MinIO/Redis 未授权访问

### 前置条件
- 完整部署的生产级环境
- 渗透测试工具: Burp Suite / OWASP ZAP / nuclei
- v0.36-v0.39 安全修复全部部署完成

### 验收标准
- [ ] 无 CRITICAL/HIGH 级别漏洞
- [ ] 所有 IDOR 端点通过测试
- [ ] RBAC 矩阵 100% 覆盖
- [ ] HTTP 安全头评分 A+（Security Headers）
- [ ] TLS 评分 A+（SSL Labs）
- [ ] 产出完整的渗透测试报告

### 预估工时
24-40 小时（含工具配置、测试执行、报告撰写）
