## 1. 当前代码现状理解

### 1.1 问题 ⑮: `_verify_project()` 重复实现

7 个 service 文件 + 1 个 export_service（方法名为 `_get_project`）中存在完全相同的租户项目验证逻辑：

| 文件 | 方法名 | 签名差异 |
|------|--------|----------|
| `doc_service.py` | `_verify_project` | `(self, project_id) -> Project` |
| `architecture_service.py` | `_verify_project` | `(self, project_id) -> Project` |
| `asset_service.py` | `_verify_project` | `(self, project_id) -> Project` |
| `conflict_service.py` | `_verify_project` | `(self, project_id) -> Project` |
| `job_service.py` | `_verify_project` | `(self, project_id) -> Project` |
| `embedding_service.py` | `_verify_project` | `(self, project_id) -> Project` |
| `search_service.py` | `_verify_project` | `(self, project_id) -> Project` |
| `export_service.py` | `_get_project` | `(self, project_id) -> Project`（逻辑完全相同）|

每个实现的逻辑完全一致：
```python
async def _verify_project(self, project_id: uuid.UUID) -> Project:
    q = select(Project).where(
        Project.id == project_id,
        Project.tenant_id == self.tenant_id,
        Project.status != "deleted",
    )
    result = await self.db.execute(q)
    project = result.scalar_one_or_none()
    if project is None:
        raise NotFoundException(error_code=ErrorCode.PROJECT_NOT_FOUND, message="项目不存在")
    return project
```

所有 8 个 service 的 `__init__` 都接收 `db: AsyncSession` 和 `tenant_id: uuid.UUID` 作为前两个参数。部分 service 还有额外参数（`user_id`、`embed_fn`、`storage` 等）。

**不受影响的 service**：
- `auth_service.py` — `__init__(db, settings)`，无 tenant_id，无 `_verify_project`
- `user_service.py` — 有 tenant_id 但无 `_verify_project`（用户操作不经过项目验证）
- `model_provider_service.py` — 有 tenant_id 但无 `_verify_project`（模型供应商不按项目隔离）
- `audit_service.py` — 有 tenant_id 但无 `_verify_project`（审计日志查询不经过项目验证）
- `project_service.py` — 有自己的项目查找逻辑（不完全相同，查找条件不同）

### 1.2 问题 ⑬: 错误消息语言不一致

全局扫描发现仅 **1 处** 英文错误消息：

| 文件 | 行 | 当前消息 | 应改为 |
|------|------|---------|--------|
| `doc_service.py` | 79 | `f"Version {version} not found"` | `f"版本 {version} 不存在"` |

其余所有错误消息均已是中文。

## 2. 本轮实施计划

### T-FIX-01: 提取 `_verify_project` 为基类 `TenantService`

**目标**: 消除 8 处重复的 `_verify_project` 实现，提取为 `TenantService` 基类。

**方案**:
1. 在 `services/api/app/services/__init__.py` 中创建 `TenantService` 基类
2. 基类提供 `db`、`tenant_id` 属性和 `_verify_project` 方法
3. 8 个 service 继承 `TenantService`，删除各自的 `_verify_project`/`_get_project`
4. 各 service 的 `__init__` 通过 `super().__init__(db, tenant_id)` 初始化公共属性，再初始化自己的额外属性
5. `export_service.py` 的 `_get_project` 改为继承自基类的 `_verify_project`，调用处对应修改

**不做的事**:
- 不改变任何 service 的公开 API（方法签名、返回值）
- 不改变任何 router 中实例化 service 的方式
- 不影响 `auth_service`、`user_service`、`model_provider_service`、`audit_service`、`project_service`（它们不含 `_verify_project`）

### T-FIX-02: 修复错误消息语言不一致

**目标**: 将 `doc_service.py:79` 的英文错误消息改为中文。

**方案**:
- `f"Version {version} not found"` → `f"版本 {version} 不存在"`

## 4. 实现约束

1. **不修改公开接口**：所有 service 的公开方法签名、返回值、异常类型保持不变
2. **不修改 router 层**：所有 router 中实例化 service 的代码不变
3. **不修改不含 `_verify_project` 的 service**：auth、user、model_provider、audit、project service 不动
4. **不引入新依赖**
5. **不修改数据库 schema**
6. **保持向后兼容**：基类使用标准 Python 继承，不引入元类或 ABC
