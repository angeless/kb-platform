## 一、当前代码现状理解

### delete() 方法（user_service.py:94-110）
- 接受 `user_id: uuid.UUID`，无 `operator_id` 参数
- 只做存在性检查（用户不存在返回 404）
- 直接将 status 设为 "disabled"
- **缺失**：不校验 user_id == operator_id（自删除）
- **缺失**：不校验被删用户是否为租户唯一管理员

### router delete_user()（users.py:110-118）
- 使用 `require_role("tenant_admin")` 做最低权限检查
- 获取 `_user: User`（当前操作者）
- 调用 `svc.delete(user_id)` 时不传 operator_id

### 管理员角色
- ROLE_HIERARCHY 中 tenant_admin=4, admin=4（legacy alias）
- 需要查询当前租户下 role 为 tenant_admin 或 admin 且 status="active" 的用户数量

---

## 二、本轮实施计划

1. 在 `delete()` 方法增加 `operator_id: uuid.UUID` 参数
2. 规则 1：如果 `user_id == operator_id`，抛出 ForbiddenException
3. 规则 2：如果被删用户 role 为 tenant_admin 或 admin，查询当前租户下还有多少个 active 的管理员
4. 如果只剩一个（即被删用户本身），抛出 ConflictException
5. router 层传入 `_user.id` 作为 `operator_id`
