# v0.16.0 上传解析状态提示 — 实施计划

## 1. 当前代码现状理解

### 已有能力
- 文件上传支持多种类型（image/audio/video/pdf/doc/zip/text）
- guess_asset_type() 按扩展名推断类型
- 解析器注册表 PARSERS 已有 text/pdf

### 问题
1. **命名不一致**: guess_asset_type() 返回 "doc"，注册表用 "document" — .docx 文件无法匹配到解析器
2. **不支持的类型静默失败**: image/audio/video 上传后创建 ingest job → parse_asset 报错 "No parser for asset_type" → job failed，但用户不知道原因
3. **用户无感知**: 上传响应中 parse_status 永远是 "pending"，没有区分"可解析"和"暂不支持"

### 用户期望
- 所有文件都能上传存储
- API 响应明确告知该文件是否可自动解析

---

## 2. 本轮实施计划

### 目标
1. 修复 PARSERS 注册表中 "document" → "doc" 的命名不一致
2. 新增 `SUPPORTED_PARSE_TYPES` 集合，在上传时判断是否可解析
3. 不可解析的文件：parse_status 设为 "unsupported"（而非 "pending"）
4. parse_asset 任务遇到 unsupported 类型时优雅退出（标记 unsupported，不标记 failed）
5. AssetOut schema 添加 parseable 提示字段

## 4. 实现约束

1. **所有文件类型都能上传** — 不拒绝任何白名单内的文件
2. **不改已有 parse_status 枚举** — 只新增 "unsupported" 值
3. **unsupported 不触发 ingest job** — 避免创建注定失败的任务
