## 一、当前代码现状理解

### 1.1 api.ts 现状

- `ApiClient` 类封装所有 API 请求
- `getToken()` 从 localStorage 读取 `access_token`
- `request()` 方法：设置 Authorization header → fetch → 检查 resp.ok → 返回/抛异常
- **无 401 重试逻辑**：access_token 过期后请求直接抛出 ApiClientError(401)

### 1.2 auth-store.ts 现状

- zustand store 管理认证状态
- `login()`: 调用 `/v1/auth/login`，**只存 access_token，忽略 refresh_token**
- `register()`: 同样只存 access_token
- `logout()`: 只清除 access_token
- `checkAuth()`: 解码 JWT payload 恢复用户信息

### 1.3 后端 API 契约

- `POST /v1/auth/login` 返回: `{ access_token, refresh_token, token_type, user }`
- `POST /v1/auth/refresh` 接受: `{ refresh_token }`，返回: `{ access_token, token_type }`
- access_token 过期时间: settings.access_token_expire_minutes（默认 30 分钟）
- refresh_token 过期时间: settings.refresh_token_expire_days * 24 * 60 分钟

## 二、本轮实施计划

### 2.1 auth-store.ts 修改

1. `login()` 和 `register()` 中同时存储 `refresh_token` 到 localStorage
2. `logout()` 中同时清除 `refresh_token`

### 2.2 api.ts 修改

1. 添加模块级变量 `refreshPromise: Promise<string> | null = null`（并发锁）
2. 添加 `refreshAccessToken()` 私有方法:
   - 读取 localStorage 中的 refresh_token
   - 如果不存在，直接返回 null
   - 调用 `POST /v1/auth/refresh`（直接用 fetch，不走 request() 避免递归）
   - 成功: 存新 access_token 到 localStorage，返回新 token
   - 失败: 清除两个 token，返回 null
3. 修改 `request()` 方法:
   - 如果 resp.status === 401 且非 /v1/auth/ 路径（避免 login/refresh 自身 401 递归）
   - 调用 `refreshAccessToken()`（使用 Promise 锁）
   - 成功: 用新 token 重试原请求
   - 失败: 清除 token，重定向到 `/login`

## 四、实现约束

1. refresh 请求用原生 fetch，不走 `request()` 方法，避免 401 递归
2. `/v1/auth/` 路径的 401 不触发刷新（login 失败就是 401，不能刷新）
3. 并发多个 401 共享同一个 refreshPromise，不重复刷新
4. 刷新失败时重定向用 `window.location.href = "/login"`
5. 不引入新依赖
