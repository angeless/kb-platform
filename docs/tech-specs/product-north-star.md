# KB Platform 产品北极星

> 确认于 2026-03-24，产品 Owner 明确定义。
> **本文件权重最高，规划任何功能前必须先读此文件。**

---

## 产品本质

**KB Platform 是一个带知识拆解和结构化层的数据库。**

不是知识管理 App，不是 AI 问答机器人，不是文档编辑器，不是协作平台。

---

## 核心链路

```
输入（多模态内容）
  → 解析 / 分类 / 建立框架和关联
  → 结构化知识图谱
  → 存入数据库
  → 可被检索和使用（输出接口）
```

保留的是：**结构 + 关联 + 可追溯性**

---

## 双向接口定位

| 方向 | 说明 |
|------|------|
| **输入接口** | 其他应用或 Agent 调用，将多模态内容（PDF、图片、音频、网页等）推入平台，由平台完成整理和入库 |
| **输出接口** | 外部 AI 系统或 Agent 调用，直接检索已结构化的知识内容 |

平台自身是**知识基础设施**，不是最终用户的消费界面。

---

## 规划功能的判断标准（三问）

规划任何功能时，先问这三个问题：

1. 这个功能是否强化了"输入 → 整合 → 图谱"核心链路？
2. 这个功能是否强化了输入接口或输出接口？
3. 如果都不是，是否是核心链路的必要支撑（安全 / 稳定性 / 基础设施）？

**三个都答"否" → 这个功能跑偏，砍掉或延期。**

---

## 典型跑偏案例（已确认不做或延后）

| 功能 | 跑偏原因 |
|------|---------|
| 多轮对话问答 | 是"用"知识库，不是"建"知识库 |
| 文件在线预览 | UI 体验优化，与核心链路无关 |
| 知识质量评分 | 过早优化，没有真实用户前无意义 |
| 暗黑模式 / 国际化 / SSO | 与核心链路完全无关 |
| 实时协作编辑 | 不是知识整合，是协作工具 |

---

## 真正应该深化的方向

核心链路的三个环节，哪里弱就补哪里：

| 环节 | 当前状态 | 应深化方向 |
|------|---------|-----------|
| **输入端** | 文本/PDF 基础能力有，OCR/音频/视频未验证 | 多模态解析覆盖和质量 |
| **整合端** | 架构生成 + MECE 门禁 + 增量五分类已有 | 关联关系质量、跨文档引用准确度 |
| **图谱端** | 数据库存储 + Wiki 浏览已有 | 图谱结构的可视化和可维护性 |
| **输出接口** | 搜索 API 已有，Agent 调用接口未系统化 | 标准化输出 API，支持外部 Agent 直接调用 |
