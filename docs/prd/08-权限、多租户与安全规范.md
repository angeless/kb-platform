# 权限、多租户与安全规范

## 1. 多租户定义
多租户是指同一平台服务多个独立客户或组织，但每个组织的数据、配置、权限、模型密钥彼此隔离。

## 2. 权限角色
### 2.1 平台超级管理员
可查看平台级配置、租户状态、系统监控，但默认不应直接浏览租户私有知识正文。

### 2.2 租户管理员
管理本租户用户、项目、模型配置、权限策略。

### 2.3 项目管理员
管理本项目的架构、文档、审核流和接入资料。

### 2.4 编辑者
可上传、编辑、提交审核。

### 2.5 审核者
可审核知识文档、冲突记录、架构变更。

### 2.6 只读成员
可查看已发布内容。

## 3. 隔离规则
- 资料、文档、架构、索引均以 tenant_id 和 project_id 隔离；
- 模型 API Key 默认租户级隔离；
- 审计日志需带 tenant_id、project_id、operator_id。

## 4. 安全要求
### 4.1 文件安全
上传文件必须经过格式校验、病毒扫描和大小限制。

### 4.2 密钥安全
模型 API Key 必须加密存储，不得明文返回前端。

### 4.3 链接安全
URL 导入必须限制协议与抓取范围，防止 SSRF 风险。

### 4.4 数据脱敏
对可能包含隐私和商业敏感内容的资料，支持脱敏策略。

### 4.5 审计可追踪
所有关键操作必须记审计日志，包括上传、审核、发布、回滚、架构修改、密钥测试。

## 5. 高风险操作
以下操作必须二次确认或具备审批：
- 发布架构大版本；
- 回滚正式知识；
- 修改节点接收规则；
- 删除项目；
- 更换默认模型路由。
