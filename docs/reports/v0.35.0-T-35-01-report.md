## 数据 / API / 状态影响

### 新增 API
- `GET /api/versions` — 返回 `{"versions": [{"version": "v1", "status": "active", "deprecation_date": null}]}`

### 新增 HTTP 头
- CORS 响应头：`Access-Control-Allow-Origin`、`Access-Control-Allow-Methods`、`Access-Control-Allow-Headers`、`Access-Control-Allow-Credentials`

### 新增配置
- 环境变量 `CORS_ORIGINS`（逗号分隔，默认 `http://localhost:3000,http://localhost:3001`）

### 无影响
- 无数据库变更
- 现有 API 契约不变
- 现有中间件链不变（CORS 在最外层，不影响内部中间件）

## 实现说明

1. **CORS 中间件位置**：通过 `add_middleware()` 最后添加，确保在中间件栈最外层。FastAPI/Starlette 的洋葱模型中，最后添加的中间件最先处理请求，这样 CORS preflight OPTIONS 请求不会被认证/限流中间件拦截。

2. **配置解析**：`cors_origins` 字符串按逗号分割并 strip 空白，空值过滤。

3. **`/api/versions` 端点**：挂在 health router 上（无认证），返回固定版本列表。未来新增 API 版本时只需扩展数组。

4. **conftest pgvector 修复**：v0.34.0 引入 `embedding_vec Vector(1536)` 列后，所有 DB 测试需要 pgvector 扩展。在 conftest 中添加 `CREATE EXTENSION IF NOT EXISTS vector`，失败时忽略（本地 PG 无 pgvector C 扩展时跳过）。

## 验证结果

> 这是 v0.34.0 遗留的环境限制，非本任务引入。

## 影响分析

- **向后兼容**：完全兼容。新增端点和中间件，不修改任何现有行为。
- **性能影响**：CORS 中间件仅在 Origin 头存在时执行匹配，开销可忽略。
- **安全影响**：CORS 限制了跨域访问源，提升安全性。默认仅允许 localhost 开发源。
