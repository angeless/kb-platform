## 1. 任务编号与目标

**T-38-02**: access_token 过期后自动使用 refresh_token 刷新，避免用户频繁重新登录。

## 2. 文件清单

| 文件 | 修改类型 | 说明 |
|------|---------|------|
| `apps/web/src/stores/auth-store.ts` | 修改 | login/register 存储 refresh_token，logout 清除 refresh_token |
| `apps/web/src/lib/api.ts` | 修改 | 添加 401 拦截器、refreshAccessToken 方法、Promise 并发锁、重试逻辑 |
| `apps/web/src/__tests__/lib/api.test.ts` | 修改 | 新增 5 个 token 刷新测试用例 |
| `docs/plans/v0.38.0-T-38-02-plan.md` | 新增 | 实施计划 |

## 3. 数据/API 影响

- **数据库变更**: 无
- **API 变更**: 无（使用已有 POST /v1/auth/refresh 端点）
- **前端行为变更**:
  - access_token 过期时自动用 refresh_token 刷新，对用户透明
  - refresh_token 也过期时自动清除 token 并重定向到 /login
  - 并发请求同时 401 时只发起一次 refresh（Promise 锁）
  - /v1/auth/ 路径的 401 不触发刷新（避免登录失败递归）

## 4. 实现说明

### 4.1 auth-store.ts 修改

- `login()` 和 `register()` 响应类型新增 `refresh_token` 字段
- 成功后同时将 `refresh_token` 存入 localStorage
- `logout()` 同时清除 `access_token` 和 `refresh_token`

### 4.2 api.ts 核心修改

1. **模块级并发锁**: `let refreshPromise: Promise<string | null> | null = null`
2. **`refreshAccessToken()` 方法**:
   - 读取 localStorage 中的 refresh_token
   - 用原生 fetch（不走 request()，避免 401 递归）调用 `POST /v1/auth/refresh`
   - 成功：存新 access_token，返回新 token
   - 失败：清除两个 token，返回 null
3. **`request()` 方法 401 拦截**:
   - 条件：`resp.status === 401 && !path.startsWith("/v1/auth/")`
   - 复用或创建 refreshPromise（`.finally()` 清除锁）
   - 刷新成功：用新 token 重试原请求
   - 刷新失败：`window.location.href = "/login"` + 抛出 ApiClientError

### 4.3 兼容性处理

- `body.data?.access_token ?? body.access_token`：兼容后端响应是否有 data 包装
- SSR 环境检测：`typeof window === "undefined"` 时跳过 localStorage 和重定向

## 6. 影响分析

- **风险**: 低。只在 api.ts 的 request() 方法中添加了 401 拦截逻辑
- **回归风险**: 无。非 401 的请求路径完全不受影响
- **依赖**: 无新增依赖
