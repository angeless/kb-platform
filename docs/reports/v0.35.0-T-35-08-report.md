## 数据 / API / 状态影响

### 无 API 变更
- 所有端点路径、请求体、响应体、状态码保持不变
- 仅影响 `/openapi.json` 输出和 `/docs` Swagger UI 展示

### OpenAPI Schema 新增
1. **BearerAuth 安全方案**：`components.securitySchemes.BearerAuth` (type: http, scheme: bearer, bearerFormat: JWT)
2. **ErrorDetail Schema**：`components.schemas.ErrorDetail` 包含 error_code, message, detail, meta 四个字段
3. **应用描述**：OpenAPI info.description 添加 "KB Platform — AI 知识整理与知识系统构建平台 API"

### 安全声明逻辑
- 公开端点（/healthz, /readyz, /metrics, /api/versions, /api/health/ready）→ `security: []`
- 其余端点 → `security: [{"BearerAuth": []}]`

## 实现说明

1. **ErrorDetail model**：在 `shared_schemas/common.py` 中定义，包含 Field 元数据（description, examples），使 OpenAPI schema 自动包含示例值。
2. **custom_openapi()**：在 `main.py` 中覆盖 `app.openapi` 方法，通过后处理 `get_openapi()` 输出注入安全方案和 security 声明。不改变现有认证逻辑。
3. **每个 router 文件**：为所有 `@router.get/post/put/patch/delete` 装饰器添加 `summary`（一句话）、`description`（详细说明）、`responses`（错误状态码 + ErrorDetail model 引用）。
4. **_RESP_AUTH 复用**：认证端点共用 `_RESP_AUTH = {401: ..., 403: ...}` 字典，减少重复代码。
5. **测试独立性**：OpenAPI 测试使用独立的 `openapi_client` fixture（不依赖数据库），使其在本地无 pgvector 环境下也能运行。

## 影响分析

- **向后兼容**：完全兼容，无 API 契约变更
- **性能影响**：首次访问 `/openapi.json` 时执行 `custom_openapi()` 后处理，结果被缓存，后续请求零开销
- **安全影响**：仅文档层面声明安全方案，不改变运行时认证逻辑
- **前端影响**：无影响。如前端使用 openapi-generator 等工具生成客户端，新的 schema 会自动包含错误类型定义
