## 任务目标
用户输入特殊字符（`&`、`(`、`|`、`!`、`:`）时搜索不崩溃，返回正常结果或空结果。

## 数据 / API / 状态影响
- **API**: 无变更（路径、参数、返回结构不变）
- **行为变更**:
  - 搜索 `hello&world` → 之前返回 500，现在返回包含 "hello" 和 "world" 的结果
  - 搜索 `!!!` → 之前返回 500，现在返回空结果
  - 搜索 `hello(world` → 之前返回 500，现在正常搜索
- **数据库**: 无变更
- **前端**: 无变更

## 实现说明

### 1. 新增 `_sanitize_tsquery_input(query)` 函数
- 使用正则 `[&|!():<>*]` 将所有 tsquery 操作符替换为空格
- 合并连续空格、去除首尾空白
- 全是操作符/空白时返回空字符串

### 2. 重写 `_build_tsquery(query)`
- 直接调用 `_sanitize_tsquery_input()` 返回清洗后的纯文本
- 不再手动拼接 `&` 和 `:*`

### 3. SQL 函数替换
- 6 处 `to_tsquery('simple', :tsquery)` → `plainto_tsquery('simple', :tsquery)`
- `plainto_tsquery` 自动处理分词和 AND 连接，不会因输入格式错误而抛异常

### 4. 降级路径
- 清洗后为空 → `_build_tsquery` 返回 `""` → `text_search()` 跳过 tsvector 直接走 ILIKE
- `plainto_tsquery` 返回空查询（全停用词）→ count=0 → 自动回退 ILIKE

- **影响范围**: 仅 `search_service.py` 的 tsquery 构建逻辑
- **行为差异**: `plainto_tsquery` 不支持前缀匹配（`:*`），但 'simple' 配置下 CJK 按字符分词，前缀匹配意义不大；且有 ILIKE 回退覆盖
- **回归风险**: 低 — ILIKE 搜索逻辑完全未改动
- **衍生任务**: 无
