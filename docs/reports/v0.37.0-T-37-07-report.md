## 1. 任务编号与目标

**T-37-07**: 防止 ZIP 炸弹消耗服务器内存和磁盘，在解压循环中增加大小限制。

| 文件 | 修改类型 | 说明 |

| `docs/plans/v0.37.0-T-37-07-plan.md` | 新增 | 实施计划 |

## 3. 数据/API 影响

- **数据库变更**: 无
- **API 变更**: 无（行为增强，不改接口契约）
- **行为变更**:
  - 单文件解压 > 100MB → 跳过，记录 error
  - 总解压 > 500MB → 停止处理，返回已处理结果 + error
  - 压缩比 > 100 → 跳过，记录 error + warning 日志
  - 以上均不抛异常，而是优雅降级返回部分结果

## 4. 实现说明

### 4.1 新增常量（第 19-20 行）

```python
MAX_ARCHIVE_TOTAL_BYTES = 500 * 1024 * 1024  # 500MB
MAX_COMPRESSION_RATIO = 100
```

### 4.2 解压循环中的三重检查（第 227-257 行）

在 `is_allowed_file()` 检查之后、`zf.read()` 之前：

1. **压缩比检查**: `info.file_size / info.compress_size > 100` → 跳过 + logger.warning
2. **单文件大小检查**: `info.file_size > self.max_upload_size_bytes` → 跳过
3. **总大小累计检查**: `total_decompressed > MAX_ARCHIVE_TOTAL_BYTES` → break
4. **读取后实际大小验证**: `len(file_content) > self.max_upload_size_bytes` → 跳过（防御伪造 ZipInfo）

### 5.3 验收标准对照

| 验收标准 | 结果 |
|---------|------|
| 解压后总大小超过 500MB 的 ZIP 被拒绝（或部分处理后停止） | ✅ 停止处理 + 返回 error |
| 包含单个 >100MB 文件的 ZIP，该文件被跳过 | ✅ 跳过 + 记录 error |
| 压缩比 >100 的文件被跳过 | ✅ 跳过 + 记录 warning + error |
| 正常 ZIP 文件导入不受影响 | ✅ 正常导入 |

## 6. 影响分析

- **风险**: 低。只在解压循环中增加前置检查，不改变已有逻辑
- **回归风险**: 无。正常大小的 ZIP 不触发任何限制
- **设计决策**: 超限时不抛异常而是返回部分结果，这是因为已处理的文件是有效的，应保留
