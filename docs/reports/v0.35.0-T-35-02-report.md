## 数据 / API / 状态影响

### 新增 API
- `GET /api/health/ready` — 深度健康检查
  - 200: status = "ok" 或 "degraded"
  - 503: status = "unhealthy"（PostgreSQL 不可用）

### 响应格式
```json
{
  "status": "ok|degraded|unhealthy",
  "version": "0.35.0",
  "checks": {
    "postgres": {"status": "ok|error", "latency_ms": 5, "message": "Connected"},
    "redis": {"status": "ok|error", "latency_ms": 2, "message": "PING successful"},
    "minio": {"status": "ok|error", "latency_ms": 8, "message": "Bucket access OK"}
  }
}
```

### 无影响
- 无数据库变更
- 现有 `/healthz` 和 `/readyz` 端点不变
- 不影响业务逻辑

## 实现说明

1. **三项并发检查**：使用 `asyncio.gather()` 并发执行 PG/Redis/MinIO 检查，减少总体响应时间。
2. **每项超时 1s**：使用 `asyncio.wait_for()` 包装，超时返回 error 状态。
3. **Redis 检查**：创建临时 `redis.asyncio.Redis` 连接，执行 `PING`，之后关闭。
4. **MinIO 检查**：使用 boto3 `head_bucket()` 检查 bucket 存在性，在 executor 中运行（boto3 是同步库）。
5. **状态聚合逻辑**：
   - PG error → unhealthy (503)
   - Redis/MinIO error + PG ok → degraded (200)
   - 全部 ok → ok (200)
6. **免限流**：将新端点加入 `EXEMPT_PATHS`，避免被限流中间件拦截。
