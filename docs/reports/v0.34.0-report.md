# v0.34.0 质量提升 — 任务汇报

## 任务信息
- **版本**: v0.34.0

## 完成内容

### 批次 A: 搜索升级

#### T-34-01: PostgreSQL 启用 pgvector 扩展
- `docker-compose.yml` 中 PostgreSQL 镜像从 `postgres:16` 切换为 `pgvector/pgvector:pg16`
- 新增 Alembic 迁移 `a1b2c3d4e5f6`: `CREATE EXTENSION IF NOT EXISTS vector`

#### T-34-02: DocEmbedding 模型迁移至 vector 类型
- `DocEmbedding` 模型新增 `embedding_vec` 字段（`Vector(1536)` 类型，nullable）
- 保留旧 `embedding` JSONB 字段（双列共存，v0.36 删除）
- `pgvector>=0.3.0` 添加到 `shared-models` 依赖
- 新增 Alembic 迁移 `b2c3d4e5f6a7`: 添加列 + 回填 JSONB → vector 数据

#### T-34-03: EmbeddingService 切换到 pgvector 查询
- `semantic_search()` 改用 SQL `<=>` 余弦距离运算符 + pgvector 原生查询
- `embed_doc()` 同时写入 `embedding` (JSONB) 和 `embedding_vec` (vector) 双列
- 保留 JSONB fallback：当 `embedding_vec` 为 null 时退化为 Python 内存计算
- 删除独立的 `cosine_similarity()` 函数

#### T-34-04: 全文搜索升级为 PostgreSQL GIN 索引
- `KnowledgeDoc` 和 `KnowledgeDocVersion` 模型新增 `search_vector` (tsvector) 字段
- 自定义 `TSVector` SQLAlchemy 类型
- GIN 索引: `ix_knowledge_doc_search_vector`, `ix_knowledge_doc_version_search_vector`
- `SearchService.text_search()` 改为 tsvector + `to_tsquery` 查询，保留 ILIKE fallback
- 支持多词 AND 查询 + `:*` 前缀匹配
- 使用 `'simple'` 文本搜索配置（兼容中文字符级匹配）
- 新增 Alembic 迁移 `c3d4e5f6a7b8`: tsvector 列 + GIN 索引 + 数据回填

### 批次 B: 前端工程化

#### T-34-05: 前端引入 React Query
- 安装 `@tanstack/react-query ^5.62.0`
- 创建 `Providers` 组件（QueryClientProvider，staleTime=30s）
- 更新 `layout.tsx` 包裹 `<Providers>`
- 创建 3 个 query hooks:
  - `useProjects()` + `useCreateProject()` — 带 invalidateQueries 自动刷新
  - `useDocs(projectId, page)` — 分页查询
  - `useJobs(projectId, page)` + `useRetryJob()` — 含 10s refetchInterval
- 迁移 3 个页面:
  - `projects/page.tsx` — 删除 useEffect/useState fetch 模式
  - `projects/[id]/docs/page.tsx` — 使用 useDocs hook
  - `projects/[id]/jobs/page.tsx` — 使用 useJobs hook + 自动刷新

#### T-34-06: 前端引入 Vitest 测试框架
- 安装 vitest ^2.1.0 + @testing-library/react ^16.1.0 + jsdom ^25.0.0
- 创建 `vitest.config.ts`（jsdom 环境，@ 路径别名）
- 10 个测试用例:
  - `StatusBadge`: 3 个（已知状态、已发布状态、未知状态 fallback）
  - `buildTree`: 3 个（构建树、空列表、孤立节点）
  - `ApiClientError`: 2 个（属性捕获、Error 实例）
  - `cn utility`: 2 个（合并类名、条件类名）

### 批次 C: 测试与修复

#### T-34-07: 跨租户隔离测试
- 新增 `test_tenant_isolation.py`，9 个测试用例
- 覆盖 9 个资源类型: Project, Asset, Doc, Architecture, Job, Conflict, Search, Export, 双向隔离
- 每个测试注册 2 个独立租户，验证跨租户访问返回 404

#### T-34-08: ASR Parser 线程安全修复
- `asr_parser.py` 新增 `threading.Lock` 保护 Whisper 模型加载
- 双重检查锁定模式（double-checked locking）
- 新增 1 个并发测试（2 线程同时调用 `parse()`）

#### T-34-09: 批量操作错误处理结构化
- `BatchFailedItem` schema 从 `{id, reason}` 改为 `{id, error_code, message}`
- 3 个批量路由（batch/review, batch/publish, batch/reject）使用 `getattr(e, "error_code", "OPERATION_FAILED")` 提取结构化错误码
