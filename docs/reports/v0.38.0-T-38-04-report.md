## 3. 数据 / API 影响

### 数据格式变化
- **旧格式**: `nonce(12B) + ciphertext`
- **新格式**: `KDF1(4B) + nonce(12B) + ciphertext`
- 已有加密数据无需迁移，decrypt() 自动识别格式
- 新加密数据自动使用新格式

### API 影响
- 无 API 变更
- encrypt/decrypt 函数签名不变

## 4. 实现说明

### 密钥派生
- `_derive_key_pbkdf2(secret)`: 使用 PBKDF2HMAC(SHA256, 100000 iterations)
- Salt: 从 secret 的 SHA-256 hash 前 16 字节派生（固定 salt，同一 key 始终产生同一密钥）
- 输出: 32 字节均匀分布密钥

### 双格式支持
- `encrypt()`: 始终使用 PBKDF2 密钥，输出带 `b"KDF1"` 前缀
- `decrypt()`: 检查前 4 字节
  - `== b"KDF1"` → 新格式，用 PBKDF2 密钥解密
  - `!= b"KDF1"` → 旧格式，用截断/填充密钥解密

### 保留旧方法
- `_derive_key()` 保留用于解密旧格式数据

## 6. 影响分析

- **安全性提升**: 密钥经过 100000 次 PBKDF2 迭代拉伸，短密钥不再被空字节填充
- **向后兼容**: 旧格式数据仍可解密，无需数据迁移
- **运行时迁移**: model_provider_service 下次更新 API Key 时自动以新格式重新加密
- **无新依赖**: cryptography 库已包含 PBKDF2HMAC
