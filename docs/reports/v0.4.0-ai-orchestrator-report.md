## 链路打通情况

```
上传资料 → 解析为 AssetChunk
→ 创建 Job(type=architecture_draft)
→ 下发 Celery orchestrator.propose_architecture(project_id, job_id)
→ Worker: 收集 chunk → 构造 Prompt → 调用 LLM → 解析 JSON
→ 写入 Architecture(status=draft) + ArchitectureNode 节点树
→ 更新 Job(status=completed)
→ 用户可通过 GET /v1/architectures/{id} 查看生成的架构
→ 用户审核后通过 POST /v1/architectures/{id}/publish 发布
```

## Prompt 设计要点
- 遵循文档 12 约束：不诱导模型编造事实，不足时标注"待确认"
- 输入：项目名称 + 行业提示 + chunk 文本（截断至 8000 字符）
- 输出：结构化 JSON（architecture_name, industry, reasoning, levels, nodes）
- node_type 限定为文档 03 定义的 6 种类型
