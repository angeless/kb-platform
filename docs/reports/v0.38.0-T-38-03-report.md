## 1. 任务编号与目标

**T-38-03**: 将 JWT 存储从 localStorage 迁移到 httpOnly cookie，防止 XSS 窃取 token。

## 3. 数据 / API 影响

### 新增 API
- `POST /v1/auth/logout` — 清除 httpOnly cookie，返回 204
- `GET /v1/auth/me` — 返回当前用户信息 {id, email, role, tenant_id}

### 修改 API
- `POST /v1/auth/login` — 响应增加 Set-Cookie (access_token + refresh_token)
- `POST /v1/auth/refresh` — 响应增加 Set-Cookie (access_token)；支持从 cookie 读取 refresh_token（body 优先）

### Cookie 配置
- `access_token`: HttpOnly=True, SameSite=Lax, Path=/, Max-Age=1800
- `refresh_token`: HttpOnly=True, SameSite=Lax, Path=/v1/auth, Max-Age=604800
- Secure 标志：通过 CORS origins 判断（localhost → False，生产 → True）

## 4. 实现说明

### 后端
- `auth.py` 提取 `_set_token_cookies()` 公共方法设置 cookie
- `_is_secure()` 根据 CORS origins 判断是否启用 Secure 标志
- `deps.py` 的 `get_current_user()` 改为 Optional authorization header，依次从 header → cookie 读取 token
- refresh 端点改为 `Optional[RefreshRequest]`，支持从 body 或 cookie 读取 refresh_token

### 前端
- `api.ts` 所有 fetch 调用添加 `credentials: "include"`，移除 `getToken()` 和手动 Authorization header
- `auth-store.ts` 移除所有 localStorage 操作；login 后调用 `/v1/auth/me` 获取用户信息；logout 调用 `/v1/auth/logout`；checkAuth 调用 `/v1/auth/me`

### 向后兼容
- Authorization: Bearer header 认证方式保留
- refresh 端点仍支持 body 传入 refresh_token

## 6. 影响分析

- **安全性提升**：token 不再存储在 localStorage，XSS 攻击无法通过 JS 读取 token
- **向后兼容**：API 调用者（非浏览器）仍可使用 Authorization header
- **register 行为**：当前 register 不返回 token / 不设置 cookie（维持现状），用户注册后需要登录
- **页面刷新**：前端通过 `/v1/auth/me` 恢复用户状态（替代原来的 JWT 解码）
