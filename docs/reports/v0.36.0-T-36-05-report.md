# T-36-05 任务汇报：修复用户角色提升漏洞

---

## 任务编号
T-36-05

## 任务目标
操作者只能邀请/修改角色不高于自身角色的用户，防止权限提升攻击。

## 修改文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `services/api/app/services/user_service.py` | 修改 | invite() 和 update() 增加 operator_role 参数和角色校验 |
| `services/api/app/routers/users.py` | 修改 | 传入 _user.role 给 invite/update 调用 |
| `services/api/tests/test_role_escalation.py` | 新增 | 9 个角色提升防护测试 |
| `docs/plans/v0.36.0-T-36-05-plan.md` | 新增 | 实施计划 |

## 数据 / API / 状态影响
- **API**: 无变更（路径、参数、返回结构不变）
- **行为变更**:
  - 邀请高于自身角色的用户：之前成功 → 现在返回 403 `AUTH_INSUFFICIENT_ROLE`
  - 将用户角色提升为高于自身角色：之前成功 → 现在返回 403
  - 同级或低级角色操作：行为不变
- **数据库**: 无变更
- **前端**: 无变更

## 实现说明

### 修改前
- `invite(email, role)` — 无 operator_role 参数，不做角色上限校验
- `update(user_id, **kwargs)` — 同上
- router 层只做 `require_role("tenant_admin")` 最低权限检查

### 修改后

#### invite() — user_service.py
```python
async def invite(self, email, role="viewer", operator_role=""):
    if operator_role and ROLE_HIERARCHY.get(role, 99) > ROLE_HIERARCHY.get(operator_role, -1):
        raise ForbiddenException(
            message="不能邀请角色高于自身的用户",
            detail={"operator_role": operator_role, "target_role": role},
        )
    # ... existing logic
```

#### update() — user_service.py
```python
async def update(self, user_id, operator_role="", **kwargs):
    target_role = kwargs.get("role")
    if operator_role and target_role is not None and ROLE_HIERARCHY.get(target_role, 99) > ROLE_HIERARCHY.get(operator_role, -1):
        raise ForbiddenException(
            message="不能将用户角色提升到高于自身的级别",
            detail={"operator_role": operator_role, "target_role": target_role},
        )
    # ... existing logic
```

#### router — users.py
```python
# invite
user = await svc.invite(email=body.email, role=body.role, operator_role=_user.role)
# update
user = await svc.update(user_id, operator_role=_user.role, role=body.role, status=body.status)
```

### 设计要点
- `operator_role` 默认为空字符串，保持向后兼容（不传时不做校验）
- 使用已有的 `ROLE_HIERARCHY` 字典做层级比较
- 使用已有的 `ForbiddenException`（错误码 `AUTH_INSUFFICIENT_ROLE`，HTTP 403）
- update() 仅在 kwargs 包含 role 且 role 不为 None 时才做校验
