## 完成内容

### T-33-11: E2E 集成测试

新增 `services/api/tests/test_e2e.py`，包含 8 个端到端测试用例，覆盖 PRD 要求的 3 大场景：

#### 场景 1: 上传 → 解析 → Pipeline 流程
| 测试 | 说明 |
|------|------|
| `test_e2e_upload_creates_asset_and_triggers_ingestion` | 上传文本文件 → 创建 Asset → 验证 metadata → 验证可通过 API 检索 |
| `test_e2e_archive_import_creates_multiple_assets` | ZIP 批量导入 → 2 个有效文件导入、1 个 .exe 跳过 → 验证文件列表 |

#### 场景 2: 安全 — ZIP 路径穿越
| 测试 | 说明 |
|------|------|
| `test_e2e_path_traversal_blocked` | `../../../etc/passwd` 路径穿越 → 返回 400 → 无 Asset 创建 |
| `test_e2e_nested_path_traversal_blocked` | `subdir/../../../../etc/shadow` 嵌套穿越 → 返回 400 |

#### 场景 3: 认证与安全
| 测试 | 说明 |
|------|------|
| `test_e2e_login_timing_attack_protection` | 存在用户错误密码 vs 不存在用户 → 相同错误码、相同消息（防枚举） |
| `test_e2e_auth_rate_limit_config` | 验证 AUTH_RATE_LIMITS 配置包含 login/register/refresh 三个端点 |
| `test_e2e_production_key_validation` | 生产环境默认密钥拒绝、短密钥拒绝、开发环境默认值放行 |
| `test_e2e_complete_auth_flow` | 完整认证流程：注册 → 登录 → 使用 token → 刷新 token → 使用新 token |

### 技术要点
- 使用 `_env_file=None` 隔离 pydantic-settings 的 `.env` 文件读取，确保生产密钥验证测试不受本地配置干扰
- JWT 刷新测试放宽断言（同秒内 token 可能相同），验证 token 存在性而非唯一性
- `_make_zip()` 工具函数创建内存 ZIP 用于路径穿越测试
