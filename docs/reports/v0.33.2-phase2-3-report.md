# v0.33.2 Phase 2 + Phase 3: Pipeline 对接 + 安全加固 — 任务汇报

## 任务信息
- **版本**: v0.33.2
- **任务**: T-33-04, T-33-06, T-33-07, T-33-08, T-33-09, T-33-10
- **日期**: 2026-03-19

## 完成内容

### T-33-04: Pipeline → AI Orchestrator 对接
- Pipeline Worker 的 4 个 stage（classify, architecture_draft, doc_generate, embed）从 HTTP（httpx.post）改为 Celery `send_task()` 调用
- 移除所有 `orchestrator_url` 参数，通过 `celery_app.send_task("orchestrator.*", queue="ai")` 路由到 AI Worker
- classify → `orchestrator.classify_incremental`
- architecture_draft → `orchestrator.propose_architecture`
- doc_generate → `orchestrator.generate_docs`
- quality_check 改为本地规则校验（内容长度、标题存在性），无需 AI 调用
- embed 改为确定性哈希伪向量（SHA-256），v0.34 将升级为 pgvector 真实嵌入
- 所有 stage 保留 fallback 降级逻辑：AI 不可用时本地兜底
- `run_pipeline` 错误处理改为新 session 更新失败状态（配合 T-33-10）

### T-33-06: ZIP 路径穿越漏洞修复
- `import_archive` 新增预检查循环：在处理任何文件前，对所有 entry 执行 `os.path.normpath()` + `..` 检测 + 绝对路径检测
- 检测到恶意路径时立即拒绝整个 ZIP（返回 400）
- 文件名提取改为 `os.path.basename(os.path.normpath(entry))`
- 移除 `db.add(asset)` 的 bug（应为 `self.db.add(asset)`）

### T-33-07: 登录时序攻击修复
- `AuthService.login()` 新增 `_DUMMY_HASH` 常量（合法 bcrypt 哈希）
- 无论用户是否存在，始终执行 `verify_password()`
- 消除通过响应时间差异枚举有效邮箱的可能性

### T-33-08: 硬编码密钥生产环境验证
- `Settings` 新增 `environment` 字段（默认 `"development"`）
- 新增 `@model_validator(mode="after")` 验证器 `validate_production_secrets`
- 生产环境（`ENVIRONMENT=production`）强制检查：
  - `jwt_secret` 不为默认值、长度 ≥ 32
  - `encryption_key` 不为默认值、长度 ≥ 32
- 开发环境不受影响（默认值可正常使用）

### T-33-09: 认证端点限流
- `RateLimitMiddleware` 新增 `AUTH_RATE_LIMITS` 配置：
  - `/v1/auth/login`: 10 次/分钟/IP
  - `/v1/auth/register`: 5 次/分钟/IP
  - `/v1/auth/refresh`: 30 次/分钟/IP
- Auth 端点始终使用 IP 作为限流 key（不依赖 JWT）
- 限流值可通过环境变量配置（`AUTH_LOGIN_RATE_LIMIT` 等）

### T-33-10: Celery Session Bug 修复
- ingestion-worker `parse_asset` 错误分支：rollback 后关闭旧 session，用 `_get_sync_session()` 新建 session 更新失败状态
- pipeline-worker `run_pipeline` 错误分支：同样改为 `sync_session_factory()` 新建 session
- 消除 "rollback 后同一 session 重查" 的不安全模式
