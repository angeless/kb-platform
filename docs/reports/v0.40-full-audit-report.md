## 一、项目总体评估

### 1.1 项目定位与面向人群

KB Platform 定位为「多模态知识整理与结构化系统」，核心价值链：**原始资料上传 → 自动解析 → AI 生成知识架构 → 知识文档生成 → 审核发布 → 全文/语义检索**。

**面向人群**：企业知识管理团队、内容编辑、技术文档团队。需要将散乱的文件（PDF、音频、图片等）自动整理为可追溯、可维护的知识体系。

**核心评价**：架构设计成熟（微服务 + 异步流水线 + 多租户），安全基础扎实（bcrypt、JWT httpOnly、SSRF 防护、ZIP 炸弹防护）。但在「最后一公里」的用户体验、WebSocket 租户隔离、前端表单验证一致性上存在短板。

## 二、架构审计

### 2.1 服务拆分评估

```
┌──────────────┐     ┌──────────────────┐     ┌─────────────────┐
│   Frontend   │────▶│   API Service    │────▶│   PostgreSQL    │
│  Next.js 15  │     │   FastAPI 3.12   │     │   + pgvector    │
└──────────────┘     └──────┬───────────┘     └─────────────────┘
                            │                         ▲
                     ┌──────▼───────┐                │
                     │    Redis     │◀───────────────┤
                     │  队列+缓存   │                │
                     └──────┬───────┘          ┌─────┴─────────┐
                            │                  │    MinIO/S3   │
                     ┌──────▼───────────┐      │   对象存储     │
                     │ Celery Workers   │──────┘
                     │ ┌── ingestion    │
                     │ ├── pipeline     │
                     │ └── ai-orchestrator │
                     └─────────────────────┘
```

**优点**：
- 4 个后端服务 + 4 个共享包，职责边界清晰
- 共享包避免了代码重复（models、schemas、config、errors）
- Celery 队列按职责分离（ingestion / pipeline / ai），避免任务抢占
- 数据库连接池区分异步（API 用 asyncpg）和同步（Worker 用 psycopg2）

**问题**：

| 编号 | 问题 | 严重度 | 说明 |
|------|------|--------|------|
| A-01 | API 版本号硬编码为 `0.35.0` | 低 | `main.py` 第 53 行 `version="0.35.0"`，但 VERSION 文件为 `0.40.3`，不一致 |
| A-02 | 前端 API 默认地址不一致 | 中 | `api.ts` 默认 `http://localhost:8000`，但 API 实际监听 `8080`，新开发者会困惑 |
| A-03 | Worker 无独立健康检查 | 中 | ingestion/pipeline/ai-orchestrator 没有 `/healthz` 端点，K8s 无法做 liveness probe |
| A-04 | 无服务发现/注册机制 | 低 | 服务间通过 Redis 队列通信，适用于当前规模，但扩展时需考虑 |

## 三、安全审计

### 3.1 高危问题

#### 🔴 S-01: WebSocket 缺少项目级租户隔离（严重度：高）

**位置**：`services/api/app/routers/ws.py` 第 36-41 行

**问题描述**：WebSocket 连接验证了 JWT 令牌和 tenant_id，但**没有验证 project_id 是否属于该租户**。

**代码片段**：
```python
tenant_id = payload.get("tenant_id")   # ✅ 提取 tenant_id
if not tenant_id:
    await websocket.close(code=4001, reason="令牌缺少租户信息")
    return
await websocket.accept()               # ❌ 直接接受，未校验 project_id
channel_name = f"job_events:{project_id}"  # ❌ 直接订阅
```

**攻击场景**：
1. 用户 A（租户 1）拥有合法 JWT
2. 用户 A 连接 `ws://api/v1/ws/jobs/{租户2的项目ID}`
3. WebSocket 接受连接，用户 A 收到租户 2 的实时任务状态

**修复建议**：在 `websocket.accept()` 之前，查询数据库验证 `project_id` 属于 `tenant_id`。

---

#### 🔴 S-02: Refresh Token 无轮换机制（严重度：中高）

**位置**：`services/api/app/services/auth_service.py`

**问题描述**：Refresh token 是纯 JWT，无数据库记录、无轮换、无吊销。泄露后在 7 天有效期内无法使攻击者失效。

**影响**：
- 如 refresh token 被截获（设备丢失、中间人攻击），攻击者可在 7 天内持续获取新 access token
- 用户无法主动使 refresh token 失效（除非等待过期）

**修复建议**：
1. 在数据库中记录 refresh token（哈希存储）
2. 每次 refresh 时生成新 token 并使旧 token 失效（轮换）
3. 检测 token 重用时，使整个 token 族失效（security event）

| 3 | 输入弱密码 | 实时提示密码强度不足 | ❌ 仅在提交时验证，无实时反馈 | 差 |
| 4 | 注册成功 | 自动登录或明确提示去登录 | ⚠️ 自动跳转到 /projects，但注册后需要手动登录 | 有歧义 |
| 5 | 登录成功 | 看到项目列表 | ✅ 显示空的项目列表 | 正常 |

### 4.2 交互问题清单

#### 🟡 UX-01: 表单验证不一致

| 页面 | 问题 |
|------|------|
| 登录 | Email 字段没有 `type="email"` 属性，允许提交无效格式的邮箱 |
| 注册 | 密码提示说"含大写字母和数字"，但后端要求大写+小写+数字+特殊字符 — 前后端验证规则不一致 |
| 重置密码 | 占位符提示"含大小写、数字和特殊字符"，但前端代码只检查长度 ≥ 8 |
| 创建项目 | 空名称时点击创建，无任何错误提示（静默失败） |

#### 🟡 UX-02: 可访问性（Accessibility）严重缺失

- 所有 `<input>` 缺少 `aria-label` 或 `<label>` 关联
- 错误提示缺少 `role="alert"`，屏幕阅读器无法感知
- 搜索模式切换按钮缺少键盘导航支持（无 `role="tablist"` / `role="tab"`）
- 无 `aria-required` 标记必填字段
- 无 focus 可视指示器定制（依赖浏览器默认，在某些主题下不可见）

#### 🟡 UX-03: 移动端不可用

- 侧边栏固定宽度 224px，在 375px 手机屏幕上占 60% 宽度
- 无汉堡菜单或折叠功能
- 无 `<meta name="viewport">` 适配指示（需确认 Next.js 是否自动添加）

#### 🟡 UX-04: 缺少 404 页面

- 项目中无 `not-found.tsx` 文件
- 访问不存在的路径（如 `/projects/nonexistent-uuid`）会显示通用错误边界
- 用户无法区分"页面不存在"和"系统错误"

#### 🟡 UX-05: 无会话过期提醒

- Access token 30 分钟过期，refresh token 7 天
- 用户长时间空闲后操作，可能突然被跳转到登录页
- 无倒计时提醒、无"即将过期"弹窗
- API client 有 401 → 自动 refresh 逻辑，但如果 refresh 也过期则直接跳转，无任何提示

#### 🟡 UX-06: 退出无确认

- 顶栏"退出"按钮直接登出，无确认弹窗
- 如果用户正在编辑文档，未保存内容将丢失

#### 🟡 UX-07: 加载状态简陋

- 所有页面使用纯文本 "加载中..." 而非骨架屏
- 首次加载体验差，尤其是慢网络环境

#### 🟡 UX-08: 错误无恢复路径

- API 错误显示为红色文字，但无"重试"按钮
- 用户必须手动刷新页面或重新导航

### 8.1 模拟专业测试人员操作

| 测试用例 | 操作 | 预期 | 实际/推测 | 结果 |
|----------|------|------|-----------|------|
| **并发上传 10 个 50MB 文件** | 同时拖拽 10 个大文件 | 顺序上传，显示队列 | 顺序上传 ✅，但 API 为每个文件读取全部到内存，10×50MB = 500MB 内存峰值 | ⚠️ |
| **上传同名同内容文件** | 上传两次相同 PDF | 第二次报告重复 | ✅ SHA-256 去重，返回 409 | 通过 |
| **上传 .exe 文件** | 拖拽可执行文件 | 拒绝上传 | ✅ 白名单过滤，不在允许列表中 | 通过 |
| **注册后立即关闭浏览器** | 注册成功后不登录 | 再次打开应跳转登录 | ✅ 无 token，跳转登录页 | 通过 |
| **连续点击 10 次登录** | 快速多次提交 | 限流或防抖 | ✅ 后端 10 req/min 限流，前端 loading 状态禁止重复提交 | 通过 |
| **超长项目名（1000 字）** | 输入极长名称 | 前端/后端截断或报错 | ⚠️ 前端无长度限制，后端 `max_length=200` 会返回 422 但前端未做预验证 | 可改进 |
| **搜索 SQL 注入尝试** | 输入 `'; DROP TABLE users;--` | 安全处理 | ✅ 使用 `plainto_tsquery()` + 参数绑定，完全免疫 | 通过 |
| **搜索 XSS 尝试** | 输入 `<script>alert(1)</script>` | 不执行脚本 | ⚠️ `ts_headline` 生成的 snippet 通过 `dangerouslySetInnerHTML` 渲染，但 ts_headline 会对 HTML 转义。风险低但代码模式不佳 | 低风险 |
| **同时开两个标签页登录不同账号** | 标签 A 登录用户 1，标签 B 登录用户 2 | 各自独立 | ⚠️ Cookie 共享域名，后登录的会覆盖先登录的 token。标签 A 的后续请求会使用用户 2 的身份 | **问题** |
| **Token 过期后操作** | 等待 30 分钟后点击按钮 | 自动刷新或提示重登 | ✅ API client 自动调用 refresh endpoint 获取新 token | 通过 |
| **Refresh token 也过期** | 等待 7 天不操作 | 优雅提示重新登录 | ⚠️ 直接跳转登录页，无"会话过期"提示 | 可改进 |
| **WebSocket 跨租户订阅** | 用租户 A 的 token 订阅租户 B 的项目 | 拒绝连接 | ❌ 接受连接并开始接收事件 | **失败** |
| **上传后断网** | 上传 50% 时断开网络 | 显示错误，支持重试 | ⚠️ XHR 会触发 error，显示"失败"，但无重试按钮 | 可改进 |
| **并发编辑同一文档** | 两人同时编辑保存 | 冲突检测或版本控制 | ✅ 基于版本号，后保存者创建 v2，不覆盖 v1 | 通过 |

## 十、总结与建议

### 10.1 整体判断

KB Platform v0.40 是一个**架构成熟、安全基础扎实的知识管理平台**。后端设计展现了专业水准：多租户隔离、防暴力破解、防 SSRF、防 ZIP 炸弹、优雅降级、结构化日志、Prometheus 指标——这些都是生产级应用的标志。

但**距离真正可用的生产部署，还需要修复 2 个安全问题 + 补齐邮件发送 + 改善新用户引导**。前端 UX 处于"功能可用但交互不够精致"的阶段，最大的问题不是 bug，而是缺少对新用户的引导和对异常情况的友好处理。

### 10.2 v0.41 建议优先级

1. **修复 WebSocket 租户隔离**（1 天）
2. **实现 refresh token 轮换**（2 天）
3. **集成邮件发送**（2 天）
4. **添加 API Key 配置检测 + 引导**（1 天）
5. **统一前后端密码验证规则**（0.5 天）
6. **添加 404 页面 + 错误恢复按钮**（0.5 天）

预计总工期：约 7 个工作日。

### 10.3 长期建议

- 补充端到端测试（Playwright）覆盖核心用户流程
- 添加 accessibility 审计到 CI（axe-core）
- 考虑 SSR/ISR 优化首屏加载
- 实现前端国际化框架
- 添加操作确认弹窗（退出、删除等不可逆操作）
- 建立 staging 环境，与 production 分离
