## 2. 完成内容

### 2.1 Job Schema 更新
- `job_type` 正则新增 `incremental`
- `JobCreate` 新增 `asset_ids` 字段

### 2.2 增量接入端点
- **新建**：`services/api/app/routers/ingestion.py`
- `POST /v1/ingestion/incremental` — 接收 project_id + asset_ids
- 创建 `incremental` 类型 Job 并调度 Celery 任务

### 2.3 Classify Prompt
- **修改**：`orchestrator/prompts.py`
- 新增 `build_classify_prompt()` — 构建增量分类 prompt
- 传入已有文档摘要 + 新 chunks，要求 LLM 输出 4 种关系类型

### 2.4 Classify Celery 任务
- **修改**：`orchestrator/tasks.py`
- 新增 `classify_incremental()` 任务
- 处理逻辑：
  - **new** → 创建新 KnowledgeDoc + Version + SourceRef
  - **supplement** → 给已有 Doc 追加新 Version
  - **correction** → 给已有 Doc 追加修正 Version
  - **conflict** → 创建 ConflictRecord

### 2.5 API 调度集成
- **修改**：`job_service.py`
- 新增 `incremental` → `orchestrator.classify_incremental` 调度分支
- 传递 `asset_ids` 列表作为第三个参数

## 5. API 说明

```
POST /v1/ingestion/incremental
Content-Type: application/json
Authorization: Bearer <token>

{
  "project_id": "uuid",
  "asset_ids": ["uuid-1", "uuid-2"]
}

→ 201 Created
{
  "data": {
    "id": "job-uuid",
    "job_type": "incremental",
    "status": "pending",
    ...
  }
}
```

任务完成后查看结果：
- `GET /v1/docs?project_id=xxx` — 查看新增/补充/修正的文档
- `GET /v1/conflicts?project_id=xxx` — 查看冲突记录

## 6. 增量分类逻辑（doc 02 section 4 对齐）

| PRD 定义 | relation_type | 处理方式 |
|----------|---------------|----------|
| 新增 | `new` | 创建新 KnowledgeDoc + Version |
| 补充 | `supplement` | 追加新 Version 到已有 Doc |
| 修正 | `correction` | 追加修正 Version 到已有 Doc |
| 冲突 | `conflict` | 创建 ConflictRecord |
