# T-36-04 任务汇报：修复文档发布状态校验

---

## 任务编号
T-36-04

## 任务目标
将 publish/review/reject/update_content 四个状态流转方法的错误码统一为 `DOC_STATUS_INVALID`，提升错误语义精确性。

## 修改文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `packages/shared-errors/shared_errors/codes.py` | 修改 | 添加 `DOC_STATUS_INVALID` 错误码 |
| `services/api/app/services/doc_service.py` | 修改 | 4 个方法的错误码从 `DOC_ALREADY_PUBLISHED` 改为 `DOC_STATUS_INVALID`，更新错误消息 |
| `services/api/tests/test_doc_status_flow.py` | 新增 | 11 个状态流转测试 |
| `docs/plans/v0.36.0-T-36-04-plan.md` | 新增 | 实施计划 |

## 数据 / API / 状态影响
- **API**: 无变更（路径、参数、返回结构不变）
- **行为变更**:
  - 状态校验失败时的 error_code 从 `DOC_ALREADY_PUBLISHED` 改为 `DOC_STATUS_INVALID`
  - publish() 错误消息更新为 `"文档当前状态不允许发布，必须先进入审核状态"`
  - HTTP 状态码仍为 409
- **数据库**: 无变更
- **前端**: 无变更（如前端依赖 error_code 做判断，需同步更新）

## 实现说明

### 修改前
四个方法（publish/review/reject/update_content）的状态校验使用 `DOC_ALREADY_PUBLISHED` 错误码，语义不精确（"已发布"≠"状态不对"）。

### 修改后
1. 在 `ErrorCode` 中新增 `DOC_STATUS_INVALID = "DOC_STATUS_INVALID"`
2. 四个方法统一使用 `DOC_STATUS_INVALID`
3. 错误消息更精确描述各方法的前置状态要求

### 错误码变更对照

| 方法 | 修改前错误码 | 修改后错误码 | 修改后消息 |
|------|-------------|-------------|-----------|
| publish() | DOC_ALREADY_PUBLISHED | DOC_STATUS_INVALID | 文档当前状态不允许发布，必须先进入审核状态 |
| review() | DOC_ALREADY_PUBLISHED | DOC_STATUS_INVALID | 只有草稿状态的文档可以提交审核 |
| reject() | DOC_ALREADY_PUBLISHED | DOC_STATUS_INVALID | 只有审核中的文档可以驳回 |
| update_content() | DOC_ALREADY_PUBLISHED | DOC_STATUS_INVALID | 只有草稿状态的文档可以编辑 |

### 保留 DOC_ALREADY_PUBLISHED
`DOC_ALREADY_PUBLISHED` 错误码保留在 `ErrorCode` 中，未删除（其他地方可能使用）。
