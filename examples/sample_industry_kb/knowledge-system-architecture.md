# 示例知识系统架构：企业内部客服与产品培训知识库

## 1. 架构目标
本架构用于整理企业内部的客服话术、产品培训、操作流程、FAQ 与版本修正规则。

## 2. 分库设计
- 主知识库：正式发布的产品、流程、FAQ 内容。
- 待审核池：AI 新生成或新更新但尚未审核的内容。
- 冲突库：不同来源结论不一致、暂不能自动合并的内容。
- 术语库：统一术语与定义。

## 3. 层级说明
- L1 领域层：客服支持、产品培训、内部制度。
- L2 模块层：退款、物流、账户、产品功能、权限配置。
- L3 主题层：某一具体问题或流程主题。
- L4 文档层：FAQ 文档、流程文档、版本说明。
- L5 证据层：录音、截图、文档、网页、视频。

## 4. 节点示例
### 节点 A1：客服支持
- 类型：领域层
- 说明：承接与用户问题处理相关的所有知识

### 节点 A1-B1：退款问题
- 类型：模块层
- 接收内容：退款政策、退款 FAQ、退款流程录屏、客服案例

### 节点 A1-B1-C1：退款 FAQ
- 类型：主题层
- 接收内容：常见问答、标准口径、异常场景处理

## 5. 新材料处理规则
- 新增退款录音转写 -> 进入待审核池，并尝试更新“退款 FAQ”或“退款流程”。
- 新版退款政策 PDF -> 触发版本修正，不直接覆盖旧政策。
- 录音口径与政策文档冲突 -> 进入冲突库。
